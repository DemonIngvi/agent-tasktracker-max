# PRD: Agent TaskTracker Max

> Файл собран из `docs/architecture/components/*/prd.md` командой `arch.py assemble`, правьте источник.

## 0. Document Purpose

Документ для владельца продукта, архитектора и разработчиков. Требования лежат в папках компонентов и пронумерованы сквозным образом.

## 1. Vision

Нужна расширяемая платформа для запуска LLM-агентов: агенты добавляются и настраиваются конфигом, без кода; модели, тулы, MCP, промпты, скиллы и память управляются централизованно; каждый запуск изолирован; расход токенов и безопасность контролируются в одной точке. Платформа должна встраиваться в ICPlan, который назначает агента на задачу.

## 2. Target User

### 2.1 Jobs To Be Done

- **Пользователь ICPlan:** быстро получить результат без ручной передачи между этапами; видеть ход работы.
- **Владелец продукта:** предсказуемые сроки и затраты, ценность для пользователей.
- **Администратор платформы:** чтобы агенты делали только разрешённое и не тратили лишнего.
- **Эксплуатация (DevOps):** стабильность, бэкапы, понятные отказы.
- **Безопасность:** нет утечек, минимальные права, аудит.
- **Тестировщик / QA:** проверяемые требования, воспроизводимые среды.
- **Агент-исполнитель:** завершить задачу с первого раза, иметь нужный контекст и доступы.
- **Агент-ревьюер:** видеть полный результат и контекст.

### 2.2 Key User Journeys

- **UJ-1. Запуск из очереди.** Начало: Запуск в очереди.
- **UJ-2. Эксплуатация: режим, ожидание, падение, вывод из работы.** Начало: Runner работает.
- **UJ-3. Проверка действия.** Начало: Действие агента.
- **UJ-4. Бюджеты, аварийная остановка, журнал.** Начало: Расход или инцидент.
- **UJ-5. Агентский цикл.** Начало: RunBundle.
- **UJ-6. Пауза, указания, лимиты, восстановление.** Начало: Шаг цикла.
- **UJ-7. Задача идёт по процессу.** Начало: Задача создана или вошла в шаг.
- **UJ-8. Управление ходом задачи пользователем.** Начало: Шаг завершён или идёт.
- **UJ-9. Агент: создать, проверить, изменить, выключить, удалить.** Начало: Нужен агент.
- **UJ-10. Процесс: создать, изменить, подключить агента, Действие.** Начало: Нужен процесс.
- **UJ-11. Обновление без простоя.** Начало: Новая версия.
- **UJ-12. Установка, доступ, локальная среда.** Начало: Чистый сервер.
- **UJ-13. Нагрузка, бэкап и восстановление, секреты.** Начало: Плановая работа или инцидент.
- **UJ-14. Вызов модели.** Начало: Вызов модели.
- **UJ-15. Смена модели и отчёт о затратах.** Начало: Нужна другая модель или отчёт.
- **UJ-16. Вызов тула.** Начало: Модель просит тул.
- **UJ-17. Подключение серверов, навыков и проверка прав.** Начало: Нужен новый тул или навык.
- **UJ-18. Память на всех уровнях M0–M6: кто пишет и кто читает.** Начало: Старт запуска.
- **UJ-19. События и чат запуска.** Начало: Шаг запуска.
- **UJ-20. Разбор задачи, трасса, польза агентов.** Начало: Вопрос о работе агентов.
- **UJ-21. Изменение настроек агента.** Начало: Изменить настройки.
- **UJ-22. Перенос агента и журнал изменений.** Начало: Перенести агента.
- **UJ-23. Среда запуска и сеть.** Начало: Нужна среда.
- **UJ-24. Рабочее пространство и репозитории.** Начало: Политика доступа.

## 3. Glossary

- **Agent Runner** — Берёт запуск из очереди ICPlan, выдаёт sandbox из тёплого пула, следит за лимитами, возвращает итог.
- **Guardrails** — Единая политика: Rego в git, данные в БД ICPlan, OPA для G1/G2; каждая точка включается в конфиге деплоя.
- **Harness** — Агентский цикл на LangGraph: контекст → LLM → тулы, hooks, пауза на approve, возобновление, стрим шагов.
- **ICPlan** — Таск-трекер It's a Plan: доска, процессы, настройка агентов, очередь запусков, UI задачи. Уже есть, дорабатываем.
- **Инфраструктура** — Кластер k3s, Helm, Traefik ingress, PostgreSQL (CloudNativePG) с PgBouncer, RustFS, секреты, бэкапы, сетевые политики, профиль нагрузки.
- **LiteLLM gateway** — Единственный выход к моделям: алиасы, virtual key на агента, лимиты, fallback. Развёрнут, не подключён.
- **MCP / Tools** — Тулы и MCP-серверы агента; правила R1–R7: MCP или прямой вызов.
- **Memory** — Память M0–M6: данные M1, M2, M5, M6 уже есть в ICPlan, подача M1 — 2.5, M5 — 2.3, чтение M6 (get_document) — 2.4; M3 — первой; M4 — вместе с RAG (после MVP).
- **Observability** — События запуска → чат запуска в задаче, затраты. Langfuse и метрики — в бэклоге.
- **Platform module** — Модуль ICPlan (своя схема в БД ICPlan): алиасы LLM, бюджеты, профили sandbox и памяти, данные guardrails, версии агентов.
- **Sandbox** — Одноразовый изолированный контейнер из тёплого пула; эфемерный /workspace, egress-прокси, доступ к репозиториям.
- **AgentDefinition** — определение агента в YAML `agent/v1` — экспорт и импорт (FR-56, FR-99)
- **AgentSettings** — настройки агента из Platform module (I4)
- **AgUiEvent** — событие протокола AG-UI
- **ApprovalDecision** — решение пользователя по вопросу или подтверждению
- **ChatCompletionRequest** — запрос к модели (OpenAI Chat Completions через LiteLLM)
- **Checkpoint** — состояние цикла (I12)
- **CostAggregate** — сводка затрат по задаче и агенту (экран «Затраты», FR-150)
- **Criterion** — критерий приёмки (AD-20)
- **Heartbeat** — ответ на продление аренды (`POST /agent-runs/:runId/heartbeat`) — обратный канал к раннеру; отмены в теле нет: отменённый запуск не `pending`, heartbeat отвечает 404 (как в форке) — Runner …
- **M3Record** — состояние задачи и передача следующему шагу (FR-39, AD-20)
- **McpToolCall** — вызов тула MCP (JSON-RPC 2.0)
- **OpaBundleData** — данные бандла OPA (`data.json`)
- **PolicyDecision** — решение OPA
- **PolicyInput** — вход OPA (G1, G2)
- **Process** — процесс типа задачи (AD-17)
- **ProcessStep** — шаг процесса (AD-17, AD-20)
- **RepoGrant** — доступ к репозиторию на один запуск
- **Run** — запуск, выданный раннеру (`POST /agent-runs/claim` → `run`)
- **RunBundle** — задание Harness от Runner (`POST /run`)
- **RunEvent** — событие запуска: конверт платформы вокруг события AG-UI (AD-21). Runner читает поток у Harness (`GET /run/events`, NDJSON) и пересылает в ICPlan (`POST /agent-runs/:runId/events`)
- **RunResult** — итог запуска (`POST /agent-runs/:runId/result`)
- **RunSummary** — итог прошлого запуска для памяти M2 — строка `agent_run` форка
- **SandboxClaim** — заявка Runner на среду запуска
- **UserMessage** — указание пользователя во время работы
- **Verdict** — вердикт по результату шага (FR-200)
- **VirtualKey** — ключ LiteLLM на агента (`/key/generate`)
- **WorkspaceSource** — источник рабочего пространства
