# icplan-integration — схема (C1)

> **Модель интеграции — pull** (решение AD-8): ICPlan ставит запуск в свою очередь, Agent Runner забирает его как внешний раннер по протоколу раннера ICPlan. Отдельного API платформы для ICPlan нет: всё идёт через существующий протокол раннера (с доработками 🛠), MCP-сервер ICPlan и API Platform module в форке. Поля — Модель данных, вызовы — каталог API ICPlan.

```
┌──────────────────────────── ICPlan (форк) ─────────────────────────────┐
│ задачи, процесс (AD-17), очередь запусков, чат запуска (AD-21), вердикт    │
│ ┌────────────────────┐  ┌──────────────────┐  ┌──────────────────────┐ │
│ │ Протокол раннера   │  │ MCP itsaplan-core│  │ Platform module API  │ │
│ │ claim · heartbeat ·│  │ задачи, коммент.,│  │ настройки, профили,  │ │
│ │ events · result    │  │ документы        │  │ доступы, манифест    │ │

└───────┼─────┼────────────────────┼───────────────────────┼─────────────┘
```

## Блоки

| Блок | Задача | Нужен? |
|---|---|---|
| Протокол раннера (`/agent-runs/*`) | выдача запуска с арендой (claim), продление и обратный канал (heartbeat), события (AG-UI) и итог | да — точка входа Agent Runner; ✅ есть, 🛠 тело heartbeat и события |
| Чат запуска в задаче | лента событий, вопросы и подтверждения с кнопками, указания, карточка итога | да — AD-21; 🛠 |
| Процесс задачи | шаг = колонка + агент + переходы; запуск по шагу; вердикт | да — AD-17, AD-20; 🛠 |
| MCP itsaplan-core | действия агента в ICPlan: задачи, комментарии, документы | да — ✅ есть |
| Platform module API | настройки агента, профили, доступы, манифест рабочего пространства | да — 🛠 модуль в форке |

## Расширения

```
новый агент      → ICPlan (UI / импорт YAML) ──▶ очередь агента ──▶ Agent Runner забирает
новый шаг        → процесс типа задачи (AD-17) ──▶ запуск по шагу
новый тул        → MCP-сервер в Registry ─────▶ через MCP-прокси Runner
новое событие    → CUSTOM AG-UI (AD-21) ────────▶ карточка в чате запуска
```

## Плюсы / минусы по модулям

| Модуль | ➕ | ➖ |
|---|---|---|
| Протокол раннера (pull) | уже есть в ICPlan; у раннера нет входящих соединений | обратный канал только в ответе heartbeat — задержка до интервала heartbeat |
| Чат запуска на AG-UI | тот же протокол и компонент, что чат агента форка | объём событий — сбор дельт в сообщения |
| Процесс задачи | задачу двигает ICPlan, агент колонку не меняет | процесс надо настроить на каждый тип задачи |
| MCP itsaplan-core | агент вызывает ICPlan как тулы | проверка G2 и обрезка вывода — в MCP-прокси Runner |
| Platform module API | наши настройки рядом с данными ICPlan | доработка форка (AGPL) |

## Роли по этапам

| Этап | Агент делает | Польз. видит | Польз. управляет | Админ видит | Админ управляет |
|---|---|---|---|---|---|
| 1 Доска | — | список досок | выбор доски | — | доступные доски |
| 2 Задача | — | форма входа | вход задачи | — | шаблон входа |
| 3 Работа | цикл LLM/тулы, события | чат запуска, артефакты, сообщения | отмена | + трейс, $ | лимиты, kill |
| 4 Approve | ждёт | что агент хочет сделать | OK / отказ | журнал решений | какие действия требуют approve |
| 5 Проверка по критериям | gate: формат — кодом, смысл — судьёй (AD-20) | карточка итога, критерии ✓ / ✗ | вердикт: принять / вернуть | статистика | готовность шага, `criteriaApproval` |
| 6 Смена статуса | — | передача след. агенту | — | — | Actions по статусам |
