## Уровни конфигурации

| Уровень | Что | Где хранится | Область |
|---|---|---|---|
| L0 | Конфиг деплоя | S9 | платформа целиком: адреса, переключатели G1–G4, режим планирования, потолки лимитов |
| L1 | [Platform module](../../platform-module/README.md) | S2 | агент: бюджеты, профили, данные guardrails, флаги планирования |
| L2 | Определение агента | S1 (+ YAML импорт) | агент: модель, инструкция, тулы, навыки, MCP, лимиты запуска |
| L3 | Запуск | задача [ICPlan](../../icplan/README.md) / [`Run`](../../../data/model-Run.yaml) | версия агента, критерии приёмки, задание |

Правило: значение берётся с самого конкретного уровня (L3 → L0), но не выше потолка L0.

## Параметры модуля

Значения и границы пересматриваются по статистике запусков (3.9) и нагрузочному тесту (4.8); правило — виды спек, таблица параметров.

Таблица перенесена в YAML компонента, см. страницу интеграций и реестры.

### Тип `resources`

`resources` — объект профиля среды `sandbox_profile` (S2), задаётся тремя параметрами выше; значение вне Мин–Макс отклоняется с именем поля.

| Поле | Тип | Единица | Колонка `sandbox_profile` | Профиль `light` (по умолчанию) | Профиль `coder` |
|---|---|---|---|---|---|
| `cpu` | number | ядра | `cpu` | 1 | не задано спекой; в границах 0,25–4 |
| `memory_mb` | int | МБ | `memory_mb` | 1024 | 2048–6144 (профиль нагрузки: «coder» 2–6 ГБ) |
| `disk_gb` | int | ГБ | `disk_gb` | 2 | не задано спекой; в границах 1–20 |
