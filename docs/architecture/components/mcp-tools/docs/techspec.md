## Сборка и поставка

1. Новый внешний сервер: строка в TECHNOLOGIES.md, лицензия, копия образа в GHCR
2. Сборка в GitHub Actions по тегу `vX.Y.Z` репозитория компонента; базовые образы закреплены по digest
3. Многостадийный Dockerfile: стадия сборки → минимальный образ запуска без компиляторов и менеджеров пакетов
4. SBOM (`syft`) и проверка уязвимостей (`trivy`, блокирует выпуск при critical)
5. Публикация в `ghcr.io/demoningvi/<имя>:<версия>` и `:<версия>-<sha>`; тег `latest` не используется
6. Кластер тянет образы с pull-секретом `ghcr-pull` (Secret в namespace)

## Обновление и откат

Собственных таблиц и миграций у [MCP / Tools](../README.md) нет: конфигурация серверов, тулов и навыков лежит в S1 (БД `itsaplan`) и откатывается вместе с api [ICPlan](../../icplan/README.md) — по Deploy [ICPlan](..\..\icplan\docs\techspec.md). Секреты серверов в БД и git не хранятся ([FR-184](../prd.md)).

1. `itsaplan-core` обновляется вместе с `itsaplan-api` по одной реплике: тулы доступны без перерыва больше времени переподключения клиента ([FR-187](../prd.md)).
2. Внешний MCP-сервер: новый образ копируется в GHCR платформы, закрепляется по digest; сервер, не прошедший проверку готовности, остаётся недоступным, остальные работают, событие эксплуатации ([FR-187](../prd.md)).
3. Откат — прежний тег и digest образа (для `itsaplan-core` — прежняя версия api); данные откатывать не нужно.
4. После обновления сервера набор его тулов сверяется с `tools/list`: новые тулы агентам не видны, пока их не добавят в allowlist (FMEA «Сервер изменил набор тулов», [FR-186](../prd.md)).

## Проверка после развёртывания

- [ ] `tools/list` возвращает разрешённые тулы

## Пример конфигурации

Как настройки лежат в развёртывании. Значения и границы параметров — в `interfaces.md` спеки (здесь новых не вводится); поля контрактов — в Модели данных.

Подключение MCP-сервера к агенту:

```yaml
mcp:
  - server: itsaplan-core
    url: http://api:3000/mcp      # агент ходит через http://agent-runner:8080/runs/<id>/mcp/itsaplan-core (AD-19)
    auth: { secret_ref: agent-key/analyst }   # ключ не попадает в контекст агента
    tools: [get_issue, add_comment, update_issue]
    timeout_s: 30
```
