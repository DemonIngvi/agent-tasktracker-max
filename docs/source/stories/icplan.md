## Процесс задачи {#process}


Однозначная модель: **тип задачи = тип процесса**, **шаг процесса = колонка + агент + переходы**, **переход делает ICPlan по итогу запуска**. Спека: icplan-agent-autopickup (FR-188, FR-189, FR-196…FR-198).

```
 Тип задачи «Исследование»                 Тип задачи «Фича»
 ┌──────────────┐  успех: процесс «Фича»   ┌──────────────┐ успех ┌──────────────┐ успех ┌──────────────┐ успех
 │ R&D          │─────────────────────────▶│ SDD          │──────▶│ Код          │──────▶│ Ревью        │──────▶ завершить
 │ агент: Ресёрч│   (тип меняется,          │ агент: Анал. │       │ агент: Разр. │       │ человек      │
 └──────┬───────┘    первый шаг «Фичи»)     └──────┬───────┘       └──────┬───────┘       └──────────────┘
        │ ошибка                                   │ ошибка               │ ошибка / лимит 3
        ▼                                          ▼                      ▼
   «Нужна помощь» (ручной шаг, владелец процесса, уведомление)

 Очередь агента «Разработчик»: все запуски, где он агент шага, по всем процессам → порядок: приоритет задачи, время постановки
```

### Термины

- **Процесс** — маршрут задачи одного типа: упорядоченные шаги, первый шаг, владелец.
- **Шаг** — колонка проекта + агент (или пусто — ручной шаг) + переход при успехе + переход при ошибке + лимит запусков.
- **Итог запуска** — успех, ошибка (в том числе лимит и непройденный quality gate), ждёт ответа, отменено человеком.
- **Очередь агента** — запуски, ждущие агента; выдаются по приоритету задачи, затем по времени.
- **Владелец процесса** — человек, которому уходит задача при ошибке шага.

Где это хранится — вкладка «Данные».

### Что пользователь видит при переходах

Правила переходов — в требованиях спеки; здесь — что появляется в истории задачи.

| Событие | Запись в истории задачи | Правило |
|---|---|---|
| Задача создана с типом, у которого есть процесс | «процесс X, шаг Y» | FR-189 «Тип задачи задаёт процесс» |
| Задача вошла в шаг с агентом | «агент взял задачу: шаг Y» | FR-188 «Агент шага процесса», FR-192 «Защита от дублей», FR-194 «Видимость подхвата» |
| Итог: успех | «итог: успех → шаг Z» | FR-197 «Переход по итогу запуска» |
| Итог: ошибка или лимит запусков | «итог: ошибка (причина) → шаг E», «лимит шага» | FR-197 «Переход по итогу запуска» |
| Итог: ждёт ответа | «ждёт ответа» | FR-197 «Переход по итогу запуска» |
| Отменено пользователем | «отменено пользователем» | FR-197 «Переход по итогу запуска» |
| Агент пытается сменить колонку | «агент: смена колонки отклонена» | FR-197 «Переход по итогу запуска» |
| Смена типа задачи | «процесс X → процесс W» | FR-189 «Тип задачи задаёт процесс» |

Чего процесс не делает (дочерние задачи вместо параллельных веток, агент не выбирает следующий шаг) — FR-196 «Определение процесса», FR-197 «Переход по итогу запуска».

Откуда у шага критерии приёмки и кто их подтверждает — FR-196 «Определение процесса» (готовность шага), FR-193 «Передача результата следующему этапу», FR-199 «Проверка пользователем перед переходом»; порядок при конфликте критериев — design AD-20.

## Истории

### US-ICP-01 {#us-icp-01}

**Как** пользователь icplan (персона П), **я хочу** создать задачу нужного типа и чтобы она сама прошла шаги процесса с агентами, **чтобы** не делегировать и не переводить задачу вручную на каждом этапе.

**Точка входа:** создание задачи: доска, Telegram-бот, API; перевод в колонку

**Критерии приёмки:**

- [ ] Задача вошла в шаг с агентом → агент — делегат, запуск в его очереди
- [ ] Успех запуска → ICPlan переводит задачу на следующий шаг
- [ ] Ошибка или непройденный quality gate → переход при ошибке, уведомление владельцу процесса
- [ ] Ручной шаг → задача ждёт человека
- [ ] Лимит запусков на шаге превышен → переход при ошибке
- [ ] Повторный вход в шаг при активном запуске → второго запуска нет

**Требования:** Агент шага процесса · Переход по итогу запуска · Защита от дублей · Поведение при отказах зависимостей

### US-ICP-08 {#us-icp-08}

**Как** пользователь icplan (персона П), **я хочу** сам поручить задачу конкретному агенту, минуя процесс, **чтобы** быстро отдать разовую работу нужному агенту.

**Точка входа:** карточка задачи: поле «делегат»

**Критерии приёмки:**

- [ ] Выбрал агента в поле «делегат» → запуск в очереди этого агента
- [ ] Задача в процессе → явный делегат важнее агента шага, шаг не меняется
- [ ] Агент выключен или не в проекте → делегат не ставится, причина в карточке

**Требования:** Приоритет правил · Получение запуска из очереди (pull) · Запуск из очереди ICPlan · Триггеры запуска ICPlan

### US-ICP-09 {#us-icp-09}

**Как** пользователь icplan (персона П), **я хочу** задать агенту вопрос или поручение упоминанием в комментарии, **чтобы** не открывать отдельный экран и не менять делегата.

**Точка входа:** комментарий с упоминанием

**Критерии приёмки:**

- [ ] `@агент` в комментарии → запуск, ответ — комментарием в той же ветке
- [ ] Упомянут агент без доступа к проекту → ответ «нет доступа», запуска нет
- [ ] Упоминание при активном запуске этого агента по задаче → сообщение попадает в текущий запуск, второго нет

**Требования:** Получение запуска из очереди (pull) · Стрим шагов и итог в задачу · Один запуск на задачу · Триггеры запуска ICPlan

### US-ICP-19 {#us-icp-19}

**Как** пользователь icplan (персона П), **я хочу** поставить агенту регулярную работу по расписанию, **чтобы** получать повторяющийся результат (отчёт, сверку) без ручного запуска.

**Точка входа:** настройки агента: расписание (`agent_schedule`)

**Критерии приёмки:**

- [ ] Расписание агента сработало → запуск в очереди, итог в задаче расписания
- [ ] Предыдущий запуск ещё идёт → новый не создаётся, запись «пропущено»
- [ ] Агент выключен → срабатывание пропущено с записью в истории
- [ ] Изменил расписание → следующие срабатывания по новому расписанию; поставил на паузу (`paused`) → срабатываний нет до возобновления; удалил → запуски по нему больше не создаются, история остаётся

**Требования:** Получение запуска из очереди (pull) · Один запуск на задачу · Триггеры запуска ICPlan

### US-ICP-02 {#us-icp-02}

**Как** пользователь icplan (персона П), **я хочу** видеть, как агент работает над задачей, **чтобы** понимать прогресс и вовремя вмешаться.

**Точка входа:** карточка задачи: чат запуска

**Участвует в цепочках ICPlan:** US-ICP-01

**Критерии приёмки:**

- [ ] Шаги появляются в задаче по мере работы
- [ ] Обрыв связи → пропущенные шаги досылаются без дублей
- [ ] Итог — комментарием агента, файлы — вложениями

**Требования:** Стрим шагов и итог в задачу · Чат запуска в задаче

### US-ICP-10 {#us-icp-10}

**Как** пользователь icplan (персона П), **я хочу** читать чат задачи с агентом и писать в него указания во время работы, **чтобы** видеть статус, вопросы и итог в одном месте и поправлять агента без перезапуска.

**Точка входа:** чат агента в задаче; Telegram-бот

**Критерии приёмки:**

- [ ] Чат показывает статус, вопросы агента и итог по порядку
- [ ] Сообщение во время работы → агент получает его на следующем шаге и подтверждает
- [ ] Запуск уже завершён → сообщение начинает новый запуск с контекстом чата
- [ ] Агент на паузе ожидания → сообщение считается ответом

**Требования:** Стрим шагов и итог в задачу · Подтверждения и ответы · Указания пользователя во время запуска

### US-ICP-11 {#us-icp-11}

**Как** пользователь icplan (персона П), **я хочу** ответить на вопрос агента, **чтобы** агент продолжил работу, а не ждал или гадал.

**Точка входа:** уведомление; чат; комментарий; Telegram-бот

**Критерии приёмки:**

- [ ] Агент задал вопрос → задача «ждёт ответа», уведомление исполнителю
- [ ] Ответ в чате, комментарии или Telegram → агент продолжает с ответом
- [ ] Нет ответа дольше таймаута → переход при ошибке с причиной «нет ответа»

**Требования:** Подтверждения и ответы · Уведомление о решении пользователя · Пауза и возобновление

### US-ICP-03 {#us-icp-03}

**Как** пользователь icplan (персона П), **я хочу** получить уведомление, когда агент ждёт моего решения или закончил, **чтобы** не держать агента в ожидании и не проверять задачи вручную.

**Точка входа:** уведомления ICPlan, Telegram

**Участвует в цепочках ICPlan:** US-ICP-11

**Критерии приёмки:**

- [ ] Запрос подтверждения или вопрос → уведомление исполнителю задачи
- [ ] Итог шага или ошибка → уведомление по настройкам пользователя (в ICPlan, Telegram)
- [ ] Нет прав на подтверждение → кнопка недоступна, решение не принимается

**Требования:** Уведомление о решении пользователя · Подтверждения и ответы

### US-ICP-12 {#us-icp-12}

**Как** пользователь icplan (персона П), **я хочу** видеть сводку по своим задачам с агентами: что выполняется и в очереди, сколько идёт, сколько открыто и закрыто, сколько потрачено токенов и денег, **чтобы** понимать загрузку, сроки и стоимость без открытия каждой задачи.

**Точка входа:** дашборд проекта; «Мои задачи»

**Критерии приёмки:**

- [ ] Сводка: в работе, в очереди, ждут меня, закрыто, открыто — с фильтром по проекту и периоду
- [ ] У задачи: время в работе агента и в ожидании человека, токены и $
- [ ] Нет запусков за период → пустая сводка с пояснением
- [ ] Данные затрат недоступны (LiteLLM) → показываются без затрат с пометкой

**Требования:** Сводка и статистика агентов · Затраты · События запуска

### US-ICP-13 {#us-icp-13}

**Как** пользователь icplan (персона П), **я хочу** принять результат агента или вернуть его с заметкой, что не выполнено, **чтобы** результат шёл дальше только после моей оценки, а агент учитывал замечания.

**Точка входа:** карточка задачи: кнопки «принято / не выполнено»; чат

**Участвует в цепочках ICPlan:** US-ICP-15

**Критерии приёмки:**

- [ ] «Принято» → переход при успехе
- [ ] «Не выполнено» с заметкой → задача возвращается на тот же шаг, заметка — в задании следующего запуска
- [ ] Возвратов больше лимита шага → переход при ошибке, владельцу процесса
- [ ] Оценка без прав (не исполнитель и не владелец) → недоступна

**Требования:** Вердикт по результату · Проверка пользователем перед переходом

### US-ICP-14 {#us-icp-14}

**Как** пользователь icplan (персона П), **я хочу** остановить процесс по задаче и при необходимости возобновить, **чтобы** агенты не продолжали работу, пока я разбираюсь.

**Точка входа:** карточка задачи; сводка

**Критерии приёмки:**

- [ ] «Остановить процесс» → активный запуск отменён, новые шаги не запускаются
- [ ] Задачу можно двигать вручную, агенты шагов не срабатывают
- [ ] «Возобновить» → запуск агента текущего шага
- [ ] Остановленная задача видна в сводке как «остановлена»

**Требования:** Отмена из ICPlan · Остановка и возобновление процесса по задаче

### US-ICP-04 {#us-icp-04}

**Как** пользователь icplan (персона П), **я хочу** отменить текущую работу агента, **чтобы** остановить неверное направление и траты.

**Точка входа:** карточка задачи, чат

**Участвует в цепочках ICPlan:** US-ICP-14

**Критерии приёмки:**

- [ ] Отмена активного запуска → `canceled`, среда уничтожена
- [ ] Отмена в очереди → запуск снят без среды
- [ ] Отмена завершённого → без изменений

**Требования:** Отмена из ICPlan · Отмена запуска

### US-ICP-15 {#us-icp-15}

**Как** пользователь icplan (персона П), **я хочу** обязать процесс по задаче проверяться со мной перед каждым переходом, **чтобы** важная задача не уходила дальше без моего согласия.

**Точка входа:** карточка задачи: переключатель «проверять со мной»

**Критерии приёмки:**

- [ ] Включил проверку → после каждого успешного шага задача ждёт моего «принято»
- [ ] «Не выполнено» → возврат на шаг с заметкой (как US-ICP-13)
- [ ] Нет ответа дольше таймаута → напоминание, задача не двигается

**Требования:** Проверка пользователем перед переходом · Вердикт по результату

### US-ICP-16 {#us-icp-16}

**Как** пользователь icplan (персона П), **я хочу** повторить шаг после ошибки или перезапустить задачу с выбранного шага, **чтобы** не создавать задачу заново.

**Точка входа:** карточка задачи

**Критерии приёмки:**

- [ ] «Повторить шаг» → новый запуск агента шага с итогом ошибки в контексте
- [ ] «Начать с шага N» → задача в колонке шага N, запуск его агента
- [ ] Лимит запусков шага исчерпан → повтор только владельцем процесса

**Требования:** Переход по итогу запуска · Передача результата следующему этапу · Повтор шага

### US-ICP-17 {#us-icp-17}

**Как** пользователь icplan (персона П), **я хочу** передать текущий шаг задачи другому агенту или человеку, **чтобы** исправить неудачный выбор исполнителя для этой задачи.

**Точка входа:** карточка задачи: поле «делегат» / «исполнитель»

**Критерии приёмки:**

- [ ] Выбрал другого агента → активный запуск отменён, запуск нового агента на том же шаге
- [ ] Выбрал человека → делегат снят, исполнитель — человек, шаг ручной для задачи
- [ ] Процесс для других задач не меняется
