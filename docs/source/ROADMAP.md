# Roadmap MVP

← README · [сводная таблица задач](TASKS.md) · [бэклог](BACKLOG.md)

Порядок: сначала [Harness](../architecture/components/harness/README.md) и конфиги агентов, затем интеграция с [ICPlan](../architecture/components/icplan/README.md), затем доработка [ICPlan](../architecture/components/icplan/README.md). Каждый этап заканчивается сценарием, который можно прокликать.

```
Этап 1: агент работает сам ─▶ Этап 2: агент работает из ICPlan ─▶ Этап 3: ICPlan ведёт процесс ─▶ Этап 4: защита и масштаб
mock-LLM + Harness + YAML     Runner + контейнер + M3              автоподхват, чат запуска, approve      пул, OPA, egress, Platform module
```

**Модель для разработки:** mock-LLM (OpenAI-совместимая, скриптовые ответы, вызовы тулов) за LiteLLM — ключ провайдера не нужен; реальная модель подключается сменой алиаса.

R&D по решениям — [docs/rnd](..\research\README.md).

## Как читать оценки

- **Человек** — рабочие дни опытного разработчика, включая тесты.
- **Агент** — время работы кодинг-агента (Claude Code) с итерациями, без времени ревью человеком.
- **Токены** — суммарно обработанные за задачу (вход с кэшем + выход), в миллионах. Выход — ~2–5% от суммы. Оценка грубая: зависит от размера кодовой базы в контексте ([ICPlan](../architecture/components/icplan/README.md) — крупный) и числа итераций.
