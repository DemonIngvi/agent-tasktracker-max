# Дальний бэклог и техдолг

Не в MVP. Компоненты учтены в архитектуре, работа по ним — после MVP.

| Тема | Что | Почему отложено | Основа |
|---|---|---|---|
| Метрики и логи | Prometheus, Grafana, Loki — развёрнуты в `itsaplan-platform`, остаются пустыми | Метриками сейчас не занимаемся, есть другие ресурсы | architecture.md → Observability |
| Langfuse / Phoenix | LLM-трейсы, evals, анализ промптов; события — экспортом OTel GenAI (соответствие в каталоге API) | Тяжёлый self-host (Langfuse: ClickHouse, Redis, S3); в MVP хватает таблицы событий; выбор — прототипом | design AD-12 |
| RAG | Индексация документов, `search_knowledge`, M4; pgvector в той же Postgres; гибридный поиск (полнотекстовый + векторы), контекст документа во фрагменте, переранжирование (R&D RAG); код — поиском по файлам | Корпус пока помещается в навигацию по документам | design AD-13 |
| A2A | Делегирование между агентами | Нет потребности; процесс ведёт ICPlan | Проект AI-агент: фаза 4 |
| web-research MCP | Выход агентов в интернет | Отдельная зона риска, нужна своя политика | architecture.md → MCP-серверы |
| Админ-MCP | `llmproxy-admin`, `guardrails-admin`, `rag-admin` | Управление пока через UI ICPlan | tool-integration |
| CI/CD, SSDLC | Gitea Actions, ArgoCD, SonarQube, ZAP, Trivy, k6 | Сначала решаем, что и как деплоим и проверяем | Проект AI-агент: `platform/technical/deployment/` |
| Функции для людей из Plane | Сравнить циклы, модули, страницы Plane с функциями ICPlan по историям; недостающее — в истории и задачи форка | Не влияет на выбор трекера; ядро — агентная часть (П1–П3) | R&D трекера, Э8 |
| «Умное» подтверждение | Вспомогательная модель оценивает риск действия; безопасное проходит, спорное — к человеку (как `approvals.mode: smart` в Hermes) | Нужна оценка ложных пропусков; сейчас подтверждение по списку `approval.tools` | R&D фреймворка, Э6 |
| Справедливая доля проектов | Порядок ждущих запусков с учётом истории потребления проекта (как admission fair sharing в Kueue) | Один проект и `aging_s` достаточно для MVP | R&D Runner, Э6 |
| M4: факты агентов (этап: после MVP, вместе с RAG; FR-41) | Движок M4 — Mem0 или LangMem поверх pgvector, выбор прототипом; функции: разрешение противоречий (Mem0), срок действия факта (Graphiti), маскирование при записи | MVP закрыт M3 + M2; факты нужны позже | R&D памяти, Э6 |
| A/B-варианты моделей и промптов | Доля трафика агента на вариант модели или промпта, сравнение по evals и вердиктам (как в TensorZero) | Нужны evals и достаточный поток запусков | R&D шлюза, Э6 |
| Детекторы содержания для G4 | PromptGuard 2 (22M) — детектор инъекций в хуке LiteLLM; AlignmentCheck — аудит трассы запуска на подмену цели (LlamaFirewall) | G4 выключен по умолчанию; AlignmentCheck экспериментальный | R&D guardrails, Э6 |
| Исполнение кода поверх MCP | Тулы как код в sandbox, загрузка только нужных определений (до −98,7% токенов, Anthropic) | Вызовы из кода обходят G2 на тул; вернуться после выноса проверки в MCP-шлюз (Q-MCP-01) | R&D MCP, Э6 |
| Агент из файла в репозитории | Импорт определения агента из файла Markdown + YAML в репозитории проекта (как `.claude/agents`, `.github/agents`) в новую версию; БД остаётся источником правды; сверка полей с Agent File (Letta) | Агентов создают администраторы в интерфейсе | R&D конфигурации, Э6 |
| Зависимости задач | Шаг процесса задачи стартует, когда закрыты родительские задачи (как parent → child в Hermes Kanban) | Нет историй с порядком между задачами | R&D автоподхвата, Э6 |
| Предупреждение агенту перед остановкой | На пороге повтора N — сообщение агенту «ты повторяешься», остановка на 2N (как пороги 3 и 6 в OpenClaw) | Сначала уточнить правило цикла (FR-118) | R&D защиты от разгона, Э6 |
| Ленивая загрузка тулов и скиллов | Поиск тулов вместо полного списка, если описания тулов > 10% окна; краткое описание скилла в промпте, инструкции — по запросу (Agent Skills) | Allowlist агента по умолчанию минимальный — порог на MVP не достигается | R&D MCP, Э6 |
| Протокол замера «один агент против цепочки» (этап: после этапа 3; FR-152, AD-27) | Эталонный набор задач в ICPlan, ≥3 прогона, парное сравнение «один агент / цепочка» с теми же моделями и лимитами, стоимость на принятую задачу со всеми ролями, часть задач отложена (holdout); n по power analysis (протокол) | Нужен работающий движок процессов (3.6, 3.7) и метрики (3.9); значения лимитов и число ролей калибруются по замеру (ворота G9) | R&D цепочка агентов |
| Прототип контура обучения агентов (этап: после MVP, этап 4, вместе с 4.4; FR-45, AD-27) | Инструментальщик собирает заметки к исходу и предлагает приращения навыков и плейбука; применение — версией настроек после регрессии и утверждения человеком, откат, чистка; оценка до/после на отложенных задачах | Прирост в цепочке не измерен (ворота G9), есть риск порчи (Misevolution); сначала замер и версии 4.4 | R&D цепочка агентов · модель памяти |
| Замер «без обучения / факты / плейбук / всё» (этап: после этапа 3 и 4.4; FR-153, AD-28) | Эталонный набор, ≥3 прогона, парное сравнение режимов обучения; стоимость на принятую задачу с учётом затрат на обучение отдельной строкой; основание сменить дефолт «выкл» для фактов на «предлагать» | Нужны движок процессов, метрики (3.9) и версии настроек (4.4); на n в десятки задач различим только крупный эффект (ворота G9) | R&D цепочки, Э9–Э10 |
| Навыки и оптимизация промптов в контуре обучения (этап: после MVP модулей «факты» и «плейбук»; FR-47, AD-28) | Адаптеры `SkillRegistry` (верификатор О5) и `PromptOptimizer` (DSPy + GEPA, пакетно на отложенном наборе); режим «применять с гейтами» как явная настройка | Сначала факты и плейбук; польза не измерена, «применять с гейтами» в продуктах не встречено | R&D цепочки, Э9 |
| Свой трекер для ИИ-агентов | Основа управления агентами — Paperclip (MIT), свой модуль задач, планирования и диаграмм; продукт для себя с возможностью продажи | Черновик на отдельный разбор; текущий выбор ICPlan не меняет | Исследование |
