## Зачем

Пять модулей получают параметры запуска через [`RunBundle`](../../architecture/data/model-RunBundle.yaml) от Runner. Слияние уровней L0–L3 с потолком L0 — общий модуль: одна реализация в Runner вместо пяти. Каждая спека при этом описывает **свои** параметры; их чтение и проверку делает задача компонента (2.1, 1.3, 2.2, 2.5, 1.4), а эта задача — только общее слияние (правило объединения задач).

Своя конфигурация, хранилища, интерфейсы и отказы каждого модуля — в задачах компонентов, не здесь.

## Что сделать

- Резолвер в Runner: L0 (конфиг деплоя) → L1 ([Platform module](../../architecture/components/platform-module/README.md)) → L2 (определение агента) → L3 (запуск), потолок L0
- Сборка параметров модулей в [`RunBundle`](../../architecture/data/model-RunBundle.yaml) с указанием источника каждого значения (уровень)
- Ошибка «нет обязательного параметра» с именем параметра и уровнем; событие при срезании до потолка

## Приёмка

- [ ] Значение берётся с самого конкретного уровня; выше потолка L0 — срезается до потолка, событие в журнале
- [ ] Нет обязательного параметра → запуск не стартует, ошибка называет параметр и уровень
- [ ] В [`RunBundle`](../../architecture/data/model-RunBundle.yaml) у каждого параметра виден уровень-источник

**Как прокликать:** задать агенту в [ICPlan](../../architecture/components/icplan/README.md) `max_steps` выше потолка → в событиях запуска «срезано до потолка L0», в [`RunBundle`](../../architecture/data/model-RunBundle.yaml) уровень L0
