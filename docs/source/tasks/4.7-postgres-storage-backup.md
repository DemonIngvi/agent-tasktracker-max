## Зачем

Одна СУБД обслуживает ICPlan, платформу и LiteLLM — нужны пул соединений, бэкапы вне узла и проверка восстановления (риск X5 ревью).

## Что сделать

- CloudNativePG: кластер PostgreSQL 17 с pgvector, БД `itsaplan` и `litellm`
- Пулер PgBouncer (transaction), список session-клиентов
- Роли БД по схемам
- RustFS: бакеты, ключи сервисов
- Бэкап: базовые копии + WAL в S3 вне узла; копия RustFS вне узла
- Ежемесячная проверка восстановления
- Задача worker форка: очистка завершённых `agent_run` и тредов чата агента по `runs.retention_days` и `chat.retention_days` по образцу `cleanupOldDeliveries`; `issue_activity` не чистится ([AD-25](..\design\define-agent-platform\design.md), [R&D](..\..\research\fork-run-retention.md))

## Приёмка

- [ ] 60 клиентов → ≤ 30 серверных соединений
- [ ] Восстановление из копии в отдельный namespace проходит
- [ ] Чужая схема недоступна роли
- [ ] 60 клиентских соединений → не более 30 серверных, запросы обслуживаются; клиенту нужен LISTEN / NOTIFY → отдельный session-пул или прямое подключение по списку; выходит версия ICPlan с миграциями → миграции до старта новых реплик, схема `platform` не затронута (FR-163)
- [ ] Агент публикует артефакт → файл в бакете `planner-attachments`; RustFS заменяется S3-совместимым → меняются только адрес и ключи; RustFS не отвечает → итог без вложений, загрузка повторяется (FR-164)
- [ ] Модуль сохраняет вложения, артефакты, копии → запись в S7; S7 недоступно → вложения не сохраняются, итоги без вложений, копии БД вне площадки не затронуты; код модуля подключается к БД платформы напрямую → невозможно, нет учётных данных и сетевого доступа (FR-171)
- [ ] Узел недоступен → платформа недоступна, восстановление из бэкапа вне узла; Postgres недоступен → сервисы не готовы, запуски не стартуют; PgBouncer исчерпал пул → запросы ждут до таймаута, ошибка с причиной; истёк TLS-сертификат → Traefik обновляет по ACME, при сбое предупреждение; переполнен диск → запись в БД и хранилище останавливается (FR-173)
- [ ] Завершённый запуск старше `runs.retention_days` без `run_event` удалён, с `run_event` — пропущен; тред чата старше `chat.retention_days` удалён; `issue_activity` на месте (FR-13)
- [ ] История задачи остаётся → комментарии и записи «агент взял / закончил» в `issue_activity` остаются, пока жива задача (FR-13)
- [ ] Очистка отключена → worker не удаляет запуски или треды соответственно, сколько бы им ни было (FR-13)
- [ ] Очистка переписки → worker удаляет `agent_chat_thread` вместе с его сообщениями и событиями (FR-13)
- [ ] Сбой очистки → строки остаются, ошибка записана в журнал worker и поднимает уведомление эксплуатации; следующий цикл очистки повторяет удаление (FR-13)
- [ ] У запуска остались события → запуск пропускается до следующей очистки (FR-13)
- [ ] Удаление в журнале → в журнал worker записано, сколько строк `agent_run` и `agent_chat_thread` удалено и по какому сроку (FR-13)
- [ ] Рост числа клиентов → Postgres держит не более 30 серверных соединений, запросы обслуживаются (FR-163)
- [ ] Сессионная функция → он подключается к отдельному session-пулу или напрямую, по согласованному списку (FR-163)
- [ ] Хранилище недоступно → итог публикуется без вложений, загрузка повторяется (FR-164)
- [ ] Копия не создалась → администратор получает предупреждение (FR-165)
- [ ] Потеря узла → данные восстанавливаются из копий вне узла (FR-165)
- [ ] Прямой доступ к БД → подключение невозможно: в среде нет учётных данных БД и сетевого доступа к ней (FR-171)

**Как прокликать:** остановить Postgres → сервисы не готовы; восстановить из копии → данные на месте
