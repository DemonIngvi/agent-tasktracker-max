## Зачем

Правила безопасности в одном месте, проверяемые и отключаемые конфигом.

## Что сделать

- Конфиг `guardrails.gN.enabled`, режим отказа
- OPA: G1 в Runner, G2 в hooks Harness
- Rego в git + `opa test`
- Аудит решений

## Приёмка

- [ ] Выключенная точка не проверяется
- [ ] Тул вне политики отклонён с причиной
- [ ] OPA недоступен → deny
- [ ] Администратор добавляет правило с точкой G2 → действует в следующих запусках агента; правило без точки → сохранение отклонено; удалено → следующие запуски без него (FR-110)
- [ ] Бюджет исчерпан → `limit_exceeded`, sandbox не создан; допуск пройден → sandbox создан; kill switch агента → отклонён до создания sandbox (FR-111)
- [ ] Тул с пометкой подтверждения → пауза до решения человека; результат тула с признаками injection → помечен или отфильтрован; тул из allowlist → без паузы; `scope: run` → повторные вызовы без паузы, `once` → пауза каждый раз (FR-112)
- [ ] `g2.enabled: false` → проверка не вызывается, в логе «G2 disabled»; все точки включены → проверки везде; неизвестная точка `g5` → сервис не стартует с ошибкой (FR-115)
- [ ] OPA не отвечает → вызов отклонён `policy_unavailable`; `on_engine_error: allow` → разрешено с пометкой «без проверки»; ответ медленнее таймаута → считается недоступным (FR-116)
- [ ] Агент R2 и опасный тул → ждёт подтверждения; R5 и релиз в prod → всё равно подтверждение; R4 и обратимое опасное действие → без паузы, с аудитом (FR-117)
- [ ] Агент R0 пытается выполнить действие → только предложение, не выполняется; R1 → каждое действие ждёт подтверждения и пишется в аудит; R3 → подтверждения требуют только необратимые действия, обратимое опасное выполняется (FR-117, определение уровней R0, R1, R3)
- [ ] Третий одинаковый вызов `get_issue` подряд → `limit_exceeded`, `loop_detected`; разные аргументы или меняющийся результат → не зацикливание; 8 шагов без изменения состояния → стоп (FR-118)
- [ ] Дневной бюджет агента достиг лимита → новые запуски отклонены, активный остановлен после шага; 80% месячного лимита проекта → уведомление, запуски идут; лимит запуска → стоп после шага (FR-120)
- [ ] Шаг в 6 раз дороже медианы → `waiting_approval` «аномальный расход»; обычный шаг → без паузы; меньше 3 шагов → только абсолютный предел (FR-121)
- [ ] Глобальный kill switch → очередь не выдаёт запуски, активные `canceled`; kill switch агента → только его запуски; снят → очередь выдаёт снова (FR-124)
- [ ] Администратор ищет причину отказа → находит правило и точку G1–G4; G2 отклонил тул → событие с точкой, правилом и причиной в чате запуска; срок событий истёк → агрегаты срабатываний сохранены (FR-125)
- [ ] Разрешённый тул → тул выполняется без паузы (FR-112)
- [ ] Неверный конфиг → сервис не стартует с понятной ошибкой (FR-115)
- [ ] Движок недоступен → вызов тула отклоняется с причиной `policy_unavailable` (FR-116)
- [ ] Задержка решения → считается недоступным, действует `on_engine_error` (FR-116)
- [ ] Первые шаги → срабатывает только абсолютный предел (FR-121)
- [ ] Скачок расхода → запуск переходит в `waiting_approval` с причиной «аномальный расход» (FR-121)
- [ ] Остановка платформы → очередь не выдаёт запуски, активные завершаются со статусом `canceled` (FR-124)
- [ ] Снятие остановки → очередь снова выдаёт запуски (FR-124)
- [ ] Разбор отказа → находит сработавшее правило и точку G1–G4 (FR-125)
- [ ] Выше максимума → значение отклонено, ошибка называет `opa.cache_ttl_s` и границы 0–300 (FR-126)
- [ ] Значение по умолчанию → применяется значение по умолчанию: 60 (FR-126)
- [ ] S11 недоступно → по `on_engine_error`: deny (по умолчанию) или allow с пометкой (FR-127)
- [ ] Запись в своё хранилище → запись попадает в S11 (OPA в памяти (bundle)) (FR-127)
- [ ] Прямой доступ к БД → подключение невозможно: в среде нет учётных данных БД и сетевого доступа к ней (FR-127)
- [ ] Аутентификация I16 → вызов не повторяется, событие с причиной (FR-128)
- [ ] Повтор I16 без дублей → дубля нет: да (FR-128)
- [ ] Таймаут I5 → вызов прерывается; повтор: нет → `on_engine_error` (FR-128)
- [ ] Битый Rego → OPA остаётся на прежнем bundle (FR-129)
- [ ] OPA недоступен → по `on_engine_error`: deny (по умолчанию) или allow с пометкой (FR-129)

**Как прокликать:** Включить G2, вызвать запрещённый тул → отказ в чате запуска
