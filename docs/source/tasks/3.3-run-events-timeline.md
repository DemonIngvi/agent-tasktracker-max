## Зачем

Пользователь хочет видеть в задаче, что делает агент и почему: реплики, рассуждения, действия, вопросы и итог — чат запуска ([AD-21](..\design\define-agent-platform\design.md), [R&D](..\..\research\run-view.md), поток).

## Что сделать

- Таблица событий запуска `run_event` (событие AG-UI целиком) в БД [ICPlan](../../architecture/components/icplan/README.md)
- Приём событий от Runner: `POST /agent-runs/:runId/events` с телом `{events: RunEvent[]}`, как у чата агента форка; маскирование; дельты `*_CONTENT` собираются в сообщение на `*_END`
- Живой поток `GET /agent-runs/:runId/stream` (SSE) и история `GET /issues/:issueId/agent-feed`
- Панель «Агент» в карточке задачи на `AgentChatPanel`: реплики, свёрнутые рассуждения и тулы, план, вопросы и подтверждения с кнопками, указания, карточка итога; разделители по шагам процесса
- Срок хранения событий
- Результат quality gate по критериям ([AD-20](../../architecture/decisions/AD-20.yaml)) — в карточке итога

## Приёмка

- [ ] Реплики агента, вызовы тулов и рассуждения (если модель их отдаёт) появляются в задаче по мере работы, без перезагрузки
- [ ] Вопрос и подтверждение — карточки с кнопками; ответ доходит до агента
- [ ] Карточка итога показывает критерии ✓ / ✗, артефакты, токены и кнопки вердикта
- [ ] Модель без рассуждений: лента на репликах, без ошибок
- [ ] Старые события удаляются по сроку
- [ ] Запуск открыт по `run_id` → последовательность шагов с входами, выходами (в пределах `events.level`) и временем; запись не удалась → Runner буферизует и дописывает позже; `TEXT_MESSAGE_CONTENT` по одному сообщению → в БД одно собранное сообщение на `*_END` ([FR-146](../../architecture/components/observability/prd.md))
- [ ] Агент работает → шаги появляются по мере выполнения; завершённый запуск → полный чат и итог; три запуска → разделены по запускам и агентам; перед тулом реплика о намерении, рассуждение по раскрытию; «агент взял задачу» не позже 10 с после взятия ([FR-147](../../architecture/components/observability/prd.md))
- [ ] Обрыв стрима → пропущенные шаги досылаются по порядковым номерам, дублей нет; итог с вложением → комментарий и вложение, без вложений → один комментарий ([FR-4](../../architecture/components/icplan/prd.md))
- [ ] Администратор открыл задачу → все запуски, версии агентов и итоги; запуск по расписанию без задачи → трассировка по агенту и расписанию; агент удалён → история показывает агента и версию на момент запуска ([FR-148](../../architecture/components/observability/prd.md))
- [ ] Разбор трассировки → события содержат `run_id`, `agent_id` и `environment`; для workflow-запуска также указан `workflow_id`; OTel GenAI mapping использует `invoke_agent`, `execute_tool`, `gen_ai.usage.*` и `gen_ai.conversation.id`, оставаясь за адаптером ([FR-148](../../architecture/components/observability/prd.md))
- [ ] Ключ API в аргументах тула → в событии `***`; значение подключённого секрета в ответе тула и секрет в промпте → маскируются до записи; событие без секретов → без изменений ([FR-149](../../architecture/components/observability/prd.md))
- [ ] Срок истёк → события удалены, агрегаты затрат сохранены; событию 10 дней при сроке 90 → доступно; срок уменьшен → старые удаляются при следующей очистке ([FR-151](../../architecture/components/observability/prd.md))
- [ ] Нет записи событий → буфер в Runner, досылка по `seq`; нет цены модели → токены учтены, стоимость «неизвестна»; переполнение таблицы событий → очистка по сроку и предупреждение эксплуатации ([FR-157](../../architecture/components/observability/prd.md))
- [ ] G2 отклонил тул → в чате запуска событие с точкой, правилом и причиной; срок хранения истёк → агрегаты срабатываний сохраняются ([FR-125](../../architecture/components/guardrails/prd.md))
- [ ] БД событий недоступна → Runner буферизует и дописывает события позже ([FR-146](../../architecture/components/observability/prd.md))
- [ ] Разбор запуска → видит последовательность шагов с входами, выходами (в пределах `events.level`) и временем ([FR-146](../../architecture/components/observability/prd.md))
- [ ] Чувствительные данные → в событии значение маскируется ([FR-146](../../architecture/components/observability/prd.md))
- [ ] Несколько запусков → чат запуска разделён по запускам и агентам ([FR-147](../../architecture/components/observability/prd.md))
- [ ] Почему агент это делает → перед вызовом в ленте есть реплика агента о намерении, а рассуждение модели (если есть) доступно по раскрытию ([FR-147](../../architecture/components/observability/prd.md))
- [ ] Разбор задачи → видит все запуски по ней, версии агентов и итоги ([FR-148](../../architecture/components/observability/prd.md))
- [ ] Нет чувствительных данных → событие записывается без изменений ([FR-149](../../architecture/components/observability/prd.md))
- [ ] Изменён срок → старые события удаляются при следующей очистке ([FR-151](../../architecture/components/observability/prd.md))
- [ ] Выше максимума → значение отклонено, ошибка называет `retention_days` и границы 7–365 ([FR-154](../../architecture/components/observability/prd.md))
- [ ] Значение по умолчанию → применяется значение по умолчанию: всё ([FR-154](../../architecture/components/observability/prd.md))
- [ ] Недопустимое значение → значение отклонено, ошибка называет `events.level` и допустимые значения ([FR-154](../../architecture/components/observability/prd.md))
- [ ] S3 недоступно → события буферизуются у Runner, запуск продолжается; чат запуска временно неполный ([FR-155](../../architecture/components/observability/prd.md))
- [ ] Аутентификация [I14](../../architecture/components/llm-gateway/integrations/I14.yaml) → вызов не повторяется, событие с причиной ([FR-156](../../architecture/components/observability/prd.md))
- [ ] Повтор [I2](../../architecture/components/agent-runner/integrations/I2.yaml) без дублей → дубля нет: да, по (run_id, seq) ([FR-156](../../architecture/components/observability/prd.md))
- [ ] Таймаут [I2](../../architecture/components/agent-runner/integrations/I2.yaml) → вызов прерывается; повтор: повтор с дедупликацией по (run_id, seq) ([FR-156](../../architecture/components/observability/prd.md))
- [ ] Запись в своё хранилище → запись попадает в S3 (Postgres [ICPlan](../../architecture/components/icplan/README.md), схема `platform`) ([FR-155](../../architecture/components/observability/prd.md))

**Как прокликать:** открыть задачу во время работы агента на mock-LLM → в панели «Агент» идут реплики и тулы; ответить на вопрос → агент продолжил; после итога — карточка с критериями
