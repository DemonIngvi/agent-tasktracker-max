## Зачем

Контроль трат и устойчивость к сбоям провайдера; базовая защита содержимого.

## Что сделать

- Бюджеты и rate limit на virtual key
- Fallback-модель
- Хуки G4: PII, injection, модерация (включаемые)
- Pre-call хук атрибуции: вызов без `metadata.run_id` отклоняется, `run_id` не того агента, что ключ, — затраты на агента ключа и событие в аудит ([FR-136](../../architecture/components/llm-gateway/prd.md), [AD-26](../../architecture/decisions/AD-26.yaml))
- Бюджет задачи `budget.issue` в иерархии run ≤ issue ≤ agent_day ≤ project_month, принудительный: Runner перед выдачей запуска и шлюз на каждом вызове; связь с защитой от зацикливания ([AD-27](../../architecture/decisions/AD-27.yaml))

## Приёмка

- [ ] Превышение бюджета → отказ
- [ ] Ошибка основной модели → ответ резервной
- [ ] Ключ в промпте маскируется
- [ ] Вызов модели без `run_id` → отклонён; вызов с `run_id` и задачей → затраты привязаны к запуску и задаче ([FR-136](../../architecture/components/llm-gateway/prd.md) «Вызов без метаданных», «Вызов с метаданными»)
- [ ] Вызов с ключом другого агента → затраты на агента ключа, событие несоответствия в аудите ([FR-136](../../architecture/components/llm-gateway/prd.md) «Чужой ключ»)
- [ ] Секрет в промпте → строка маскируется до отправки провайдеру; чистый промпт → запрос без изменений; ответ нарушает политику модерации → блокируется, агент получает отказ ([FR-114](../../architecture/components/guardrails/prd.md))
- [ ] Расход агента за сутки достиг лимита → новые запуски отклонены со статусом `limit_exceeded`; проект набрал 80% месячного лимита → администратор получает уведомление, запуски идут; запуск потратил лимит токенов → остановка после текущего шага ([FR-120](../../architecture/components/guardrails/prd.md))
- [ ] Суммарный поток токенов превысил TPM модели → вызовы ждут или отклонены с ошибкой лимита; поток ниже TPM → без задержки; агент превысил свой RPM → ждёт только он ([FR-123](../../architecture/components/guardrails/prd.md))
- [ ] Агент превысил лимит частоты → ошибка лимита; ниже лимитов → вызов проходит; бюджет virtual key исчерпан → отказ до обращения к провайдеру ([FR-138](../../architecture/components/llm-gateway/prd.md))
- [ ] Основная модель недоступна → запрос выполняет резервная, факт в трейсе; резерв не задан → ошибка вызова, [Harness](../../architecture/components/harness/README.md) повторяет; обе недоступны → ошибка `all_providers_failed` ([FR-139](../../architecture/components/llm-gateway/prd.md))
- [ ] Провайдер недоступен → fallback-модель, если нет — ошибка вызова; БД `litellm` недоступна → проверка бюджетов невозможна, вызовы отклонены ([FR-144](../../architecture/components/llm-gateway/prd.md))
- [ ] Бюджет задачи исчерпан → новый запуск по задаче не выдаётся, текущий остановлен со статусом `limit_exceeded`, задача — по переходу при ошибке ([FR-120](../../architecture/components/guardrails/prd.md)); `budget.issue` выше остатка `agent_day` → предупреждение, действует меньший остаток
- [ ] Осталась одна единица бюджета задачи, одновременно поступили 20 запросов → сумма резервов и списаний не превышает остаток; запрос без резерва не передаётся провайдеру ([FR-120](../../architecture/components/guardrails/prd.md), [AD-29 F1](..\..\research\dev-deploy-monitoring.md))
- [ ] В пределах лимита → вызовы проходят без задержки ([FR-123](../../architecture/components/guardrails/prd.md))
- [ ] В пределах лимита → вызов проходит ([FR-138](../../architecture/components/llm-gateway/prd.md))
- [ ] Провайдер недоступен → запрос выполняется резервной моделью, факт фиксируется в трейсе ([FR-139](../../architecture/components/llm-gateway/prd.md))

**Как прокликать:** LiteLLM UI: бюджет агента; mock-сценарий ошибки → ответ fallback
