## Зачем

Без тулов агент только отвечает текстом. Allowlist из конфига — первая граница безопасности (до OPA).

## Что сделать

- Подключение MCP-серверов из определения агента (адаптер MCP → тулы LangGraph)
- Allowlist: агенту видны только перечисленные тулы
- Таймауты и ошибки тулов возвращаются агенту как результат, цикл продолжается
- Тестовый MCP-сервер (echo / файлы) для проверок
- Описание рабочего пространства в контексте, тулы только внутри `/workspace`, артефакты в `RunResult`

## Приёмка

- [ ] Агент вызывает тул MCP и получает результат
- [ ] Тул вне allowlist не виден и не вызывается
- [ ] Таймаут тула → ошибка в результате, запуск не падает
- [ ] Новый MCP-сервер добавлен агенту → тулы доступны со следующего запуска; сервер не отвечает при регистрации → пометка «недоступен», тулы не выдаются; тот же адрес повторно → отклонено как дубликат (FR-176)
- [ ] Тул ответил вовремя → результат агенту; ответ больше лимита → обрезан с пометкой, контекст не переполняется (FR-178)
- [ ] MCP-сервер недоступен → ошибка тула агенту; секрет не задан → тулы сервера недоступны, предупреждение; сервер изменил набор тулов → новые тулы не видны без allowlist (FR-186)
- [ ] MCP-сервер недоступен → ошибка тула возвращается агенту, цикл продолжается (FR-34)
- [ ] Запуск с манифестом из двух источников → агент видит пути и права; файловый тул с путём вне `/workspace` → отклонён; итог → `RunResult` со списком артефактов; изменён lock-файл и вызван `install_dependencies` → шаг подготовки повторён, `/workspace/.deps` обновлён (FR-29)
- [ ] Новые зависимости → Runner повторяет шаг подготовки (AD-19), `/workspace/.deps` обновлён, цикл продолжается (FR-29)
- [ ] Описание в контексте → агент видит пути и права в контексте (FR-29)
- [ ] Вызов в обход Harness → соединение недоступно: MCP-серверы доступны только через MCP-прокси Runner, вызов вне allowlist прокси отклоняет (FR-177)
- [ ] Недоступный MCP → агент получает ошибку тула и продолжает цикл (FR-178)
- [ ] Успешный вызов → результат возвращается агенту (FR-178)
- [ ] Выше максимума → значение отклонено, ошибка называет `timeout_s` и границы 5–300 (FR-183)
- [ ] Значение по умолчанию → применяется значение по умолчанию: itsaplan-core (FR-183)
- [ ] Нет обязательного поля → сохранение отклонено, ошибка называет `auth.secret_ref` (FR-183)
- [ ] S1 недоступно → тулы ICPlan возвращают ошибку агенту с типом «недоступно»; агент не повторяет записи сам (FR-184)
- [ ] Запись в своё хранилище → запись попадает в S1 (PostgreSQL 17 (CloudNativePG), БД `itsaplan`) (FR-184)
- [ ] Аутентификация I17 → вызов не повторяется, событие с причиной (FR-185)
- [ ] Неидемпотентный вызов I9 → автоматического повтора нет, решение принимает вызывающий (FR-185)
- [ ] Таймаут I9 → вызов прерывается; повтор: чтение — 2 раза; запись — нет (FR-185)
- [ ] Новый тул на сервере → агенту он не виден (FR-177)

**Как прокликать:** автотест сценария на mock-LLM (CLI-запуск, вывод шагов): в шагах виден вызов тула и его ответ
