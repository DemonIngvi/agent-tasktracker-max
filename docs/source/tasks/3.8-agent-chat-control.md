## Зачем

Пользователь поправляет агента без перезапуска, администратор проверяет агента в чате до подключения к процессу и временно выключает агента. Основа есть в ICPlan: канал чата раннера (`/agent-chats/*`) с возобновлением сессии и ответ heartbeat запуска.

## Что сделать

- ICPlan: признак `agent.enabled` — не создавать и не выдавать запуски выключенного агента; выбор судьбы активных
- ICPlan: сообщение агенту по задаче при активном запуске прикрепляется к запуску; ответ heartbeat отдаёт сообщения и признак отмены
- Runner: читать сообщения и отмену из heartbeat, передавать в Harness (I7)
- Harness: указания пользователя в цикле, «стоп»
- Runner: обслуживать канал чата ICPlan для проверки агента; изменение задач из тестового чата — с подтверждением

## Приёмка

- [ ] Сообщение во время запуска учтено агентом на следующем шаге, в истории «получено агентом»
- [ ] Выключенный агент не получает запусков; после включения очередь разбирается
- [ ] В тестовом чате изменение задачи требует подтверждения
- [ ] Сообщение пришло после завершения запуска → создаётся новый запуск с контекстом чата; сообщение «стоп» → запуск завершается с итогом сделанного (FR-10 «Запуск завершён», «Стоп»; FR-28 «Стоп»)
- [ ] Сообщение во время вызова тула → учитывается после завершения тула, в событиях «учтено» (FR-28 «Указание», «Во время тула»)
- [ ] Выключить агента с «доделать» → активные завершаются, новые не создаются, у задач причина «агент выключен»; с «отменить» → активные отменены, Runner узнаёт по heartbeat (FR-11 «Выключение», «Отмена активных», «Включение»)
- [ ] Сообщение во время работы → сообщение прикреплено к запуску, Runner получает его со следующим heartbeat, в истории «получено агентом» (FR-10)
- [ ] Mock-модель → ответы по сценарию mock, затрат нет (FR-12)

**Как прокликать:** чат с агентом на mock-LLM → ответ и шаги в чате; задача в работе → написать «используй pytest» → в чате запуска «учтено»
