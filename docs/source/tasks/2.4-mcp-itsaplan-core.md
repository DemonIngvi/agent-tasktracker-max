## Зачем

Агент должен читать задачу, писать комментарии и менять статус — иначе процесс между этапами не работает.

## Что сделать

- Подключение MCP ICPlan в определении агента
- Ключ агента для MCP без попадания в контекст
- Allowlist тулов (issue.*, docs.*)
- Чтение M6: `get_document`, запись в документы проекта агенту недоступна

## Приёмка

- [ ] Агент читает задачу и пишет комментарий → данные и комментарий в задаче от имени агента (FR-182, «Работа с задачей»)
- [ ] Агент меняет статус задачи вне процесса → статус изменён
- [ ] MCP проекта выключен → тулы ICPlan недоступны, запуск завершается с причиной (FR-182, «MCP выключен в проекте»)
- [ ] `update_issue` со сменой колонки задачи в процессе → смена отклонена, остальные поля обновлены (FR-182, «Смена колонки в процессе»)
- [ ] Запуск получен из очереди ICPlan → используется прямой API, не MCP (FR-179, «Внутренний вызов»)
- [ ] Доступ к git-провайдеру нужен нескольким агентам → подключён как MCP-сервер, секрет на стороне сервера (FR-179, «Тул для нескольких агентов»)
- [ ] Обработка 500 записей → прямой вызов, не тул модели (FR-179, «Пакетная операция»)
- [ ] Проверки G1–G4 (guardrails) и автозапись M1/M2 → прямой вызов, не тул модели и не MCP (FR-179, правило выбора; сами проверки реализует 4.3)

- [ ] Агенту нужен документ проекта → читает тулом `get_document`; попытка записи в документ → недоступна (FR-36, «Чтение M6»)

**Как прокликать:** Делегировать задачу → агент оставил комментарий и сменил статус
