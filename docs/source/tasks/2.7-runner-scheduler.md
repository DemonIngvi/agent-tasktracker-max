## Зачем

Агентов несколько, они делят модели и могут работать параллельно или только по одному. Без планировщика агенты упираются в лимиты провайдера, а два запуска по одной задаче конфликтуют. Решение — вариант B ([design AD-14](..\design\define-agent-platform\design.md)).

## Что сделать

- Конфиг `scheduling`: `mode`, `global_max`, `per_issue`, `order`, `agents.<id>.parallel/max`, `models.<alias>.max`
- Слоты: глобальный, агента, модели, задачи; запуск стартует, когда свободны все
- Статус `queued` и порядок `fifo` / `priority`
- Общие слоты для нескольких экземпляров Runner (Postgres)
- Метрики очереди: сколько ждёт, почему (какой слот занят)

## Приёмка

- [ ] `sequential`: три запуска разных агентов идут по одному
- [ ] Агент с `parallel: false` никогда не идёт в два потока
- [ ] Занят слот модели → запуск ждёт в `queued` и стартует после освобождения
- [ ] Второй запуск по той же задаче ждёт первого
- [ ] Два экземпляра Runner соблюдают `global_max` суммарно
- [ ] Два экземпляра Runner опросили очередь одновременно → запуск получил один; повторный опрос не выдаёт взятый запуск (FR-3)
- [ ] `parallel` при `global_max: 4` и трёх запусках разных агентов → все три идут одновременно; агенту `parallel: false` второй запуск ждёт первого в любом режиме (FR-68)
- [ ] Запуск перешёл в `waiting_approval` → глобальный слот и слот модели освобождены; второй запуск той же задачи ждёт, слот задачи занят; решение принято при занятых слотах → запуск в `queued`, продолжает с того же шага (FR-69)
- [ ] Два запуска по разным задачам → идут одновременно; активный запуск по задаче упал → следующий по задаче стартует (FR-70)
- [ ] События запусков и слоты планировщика пишутся в S3; S3 недоступно → новые запуски не стартуют, события активных буферизуются; доступ вне S3, S5 закрыт ролью БД (FR-78)
- [ ] Конкурентный тест 2.7.7: лимиты не превышены, низкий приоритет не голодает
- [ ] Старение приоритета → его приоритет повышается на уровень за каждый такой интервал, запуск не голодает (FR-67)
- [ ] Агент без параллели → второй ждёт завершения первого в любом режиме (FR-68)
- [ ] Параллельный режим → все три идут одновременно (FR-68)
- [ ] Последовательный режим → они выполняются по одному в порядке очереди (FR-68)
- [ ] Два агента на одну задачу → второй ждёт завершения первого (FR-70)
- [ ] Первый упал → следующий запуск по задаче стартует (FR-70)

**Как прокликать:** включить `sequential`, делегировать три задачи разным агентам → в ICPlan видно, что они выполняются по очереди; переключить на `parallel` → одновременно.
