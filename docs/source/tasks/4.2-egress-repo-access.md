## Зачем

Агенту-разработчику нужен код, но без утечки секретов и без доступа куда не положено.

## Что сделать

- Egress-прокси с allowlist
- Короткоживущие токены репозиториев на запуск
- Клон в `/workspace`, ветка `agent/<KEY>`, PR
- MCP git-провайдера

## Приёмка

- [ ] Запрещённый домен блокируется
- [ ] Токена нет в env
- [ ] Push в main отклонён, PR создаётся
- [ ] Запуск завершён → `/workspace` удалён, код в ветке `agent/<KEY>`, файл-результат загружен во вложения до уничтожения; диск переполнен → запись отклонена, ошибка запуску ([FR-84](../../architecture/components/sandbox/prd.md))
- [ ] Запись вне `/workspace` → запрещена, в `/workspace` разрешена; `g3.enabled: false` → профиль не применяется, предупреждение в логе старта ([FR-113](../../architecture/components/guardrails/prd.md))
- [ ] Runner обращается к API [ICPlan](../../architecture/components/icplan/README.md) → разрешено; контейнер запуска подключается к Postgres напрямую → блокируется; новый интерфейс в `interfaces.md` → политика дополнена до выпуска ([FR-167](../../architecture/components/infrastructure/prd.md))
- [ ] Разрешённый хост → соединение проходит через egress-прокси ([FR-87](../../architecture/components/sandbox/prd.md))
- [ ] Вызов тула с ключом → ключ подставляется прокси, агент его не видит ([FR-88](../../architecture/components/sandbox/prd.md))
- [ ] Ключ MCP-сервера → учётные данные сервера подставляет MCP-прокси Runner, в sandbox их нет ([FR-88](../../architecture/components/sandbox/prd.md))
- [ ] Секрет в выводе → прокси не возвращает подставленный секрет агенту ([FR-88](../../architecture/components/sandbox/prd.md))
- [ ] Запрещённый домен → соединение блокируется и событие фиксируется ([FR-87](../../architecture/components/sandbox/prd.md))

**Как прокликать:** Делегировать задачу «поправь README» → в репозитории PR от агента
