## Зачем

Тип задачи задаёт процесс, шаг процесса — колонку и агента. Задача, вошедшая в шаг, сама уходит агенту: без ручного делегирования на каждом этапе.

## Что сделать

- Таблицы `process` и `process_step` в форке ICPlan (тип задачи → процесс, шаг = колонка + агент + переходы + лимит)
- Проверка структуры процесса при сохранении
- Редактор процесса в настройках проекта
- Вход задачи в шаг (перевод, создание задачи типа) → делегат + запуск в очереди агента
- Приоритет правил, защита от дублей, очистка при выходе агента

## Приёмка

- [ ] Сохранить процесс с переходом на несуществующий шаг, повтором колонки или двумя переходами при успехе → отказ с шагом и причиной (FR-196 «Ошибка структуры», «Один переход при успехе»)
- [ ] Создать задачу типа с процессом → она на первом шаге, делегат — агент шага, один запуск в очереди; тип без процесса → обычная доска (FR-189 «Создана задача типа», «Тип без процесса»)
- [ ] Сменить тип задачи на тип с процессом → задача на первом шаге нового процесса, активный запуск прежнего шага отменён (FR-189 «Смена типа»)
- [ ] Дважды перевести задачу в колонку шага при активном запуске → в очереди один запуск; после завершения запуска — новый (FR-192 «Повторный вход в шаг», «После завершения»)
- [ ] Шаг с агентом Y, Действие с агентом Z, явный делегат при переводе → делегат по приоритету: явный → шаг → Действие, запуск один (FR-191, FR-192 «Разные агенты»)
- [ ] Ручной шаг → делегат снят, запуска нет (FR-188 «Ручной шаг»)
- [ ] В шаге агент не из проекта → запуска нет, в истории предупреждение; снять агенту проект → шаги ручные, у других проектов без изменений (FR-188 «Агент не участник проекта», FR-195)
- [ ] Постановка в очередь не удалась → делегат установлен, повтор с backoff до 60 с, до 5 попыток, затем запись «запуск не поставлен» и уведомление владельцу процесса; после восстановления очереди «повторить шаг» создаёт один запуск (FR-211 «Очередь недоступна», «Восстановление после неудачной постановки»)
- [ ] Вход в шаг сверх `step.max_runs` → запуск не создаётся, задача идёт по переходу при ошибке с причиной «лимит шага» (FR-211 «Цикл переходов»)
- [ ] Делегат — человек → запуск агента отменён, делегат-агент снят, работу ведёт выбранный человек; шаг для этой задачи ручной до следующего входа в шаг (FR-191)
- [ ] Агент удалён → ссылки на него сняты во всех проектах (FR-195)
- [ ] Выше максимума → значение отклонено, ошибка называет `step.max_runs` и границы 1–10 (FR-208)
- [ ] Значение по умолчанию → применяется значение по умолчанию: нет (FR-208)
- [ ] Нет обязательного поля → сохранение отклонено, ошибка называет `process.issue_type` (FR-208)
- [ ] S1 недоступно → итог не принимается и остаётся у Runner, который повторяет отправку (FR-17); переход по итогу выполняется, когда итог принят (FR-209)
- [ ] Права по I20 → API ICPlan отклоняет запрос (403), данные не меняются, событие в журнале (FR-210)
- [ ] Таймаут I1 → вызов прерывается; повтор: backoff до 60 с (FR-210)
- [ ] Декомпозиция — дочерние задачи → он создаёт дочерние задачи тулом `create_issue`, у каждой свой тип и свой процесс; сам процесс задач не создаёт (FR-196)
- [ ] Корректный процесс → процесс сохранён, у каждого шага одна колонка и явные переходы (FR-196)
- [ ] Запись в своё хранилище → запись попадает в S1 (PostgreSQL 17 (CloudNativePG), БД `itsaplan`) (FR-209)

**Как прокликать:** Настройки проекта → Процессы: задать процесс «Фича» → создать задачу «Фича» → агент первого шага взял её
