## Зачем

Первая связь с ICPlan: задачи из очереди ICPlan выполняет наш Harness, а не CLI на машине оператора.

## Что сделать

- Каркас Runner (Go)
- Опрос очереди ICPlan по ключу агента (протокол `@itsaplan/runner`)
- Запуск Harness, приём событий, стрим ответа в ICPlan, итог
- Таймаут и отмена
- Параллельность на агента
- Манифест рабочего пространства из политики доступа → Sandbox и `RunBundle`

## Приёмка

- [ ] Делегированная внешнему агенту задача → ответ в комментарии
- [ ] Отмена в ICPlan останавливает запуск
- [ ] Таймаут → статус failed с причиной
- [ ] Задача делегирована внешнему агенту → запуск в очереди ICPlan, Runner его забирает; задача внутреннему агенту — Runner не забирает; отозванный ключ → отказ в доступе, запуски не выдаются (FR-1)
- [ ] Очередь пуста → Runner ждёт интервал опроса без ошибок; Runner остановлен → запуск ждёт и исполняется после старта; очередь не отвечает → опрос с растущей задержкой и событие о недоступности (FR-2)
- [ ] Два экземпляра Runner опрашивают одновременно → запуск получает один; Runner упал после получения → по истечении аренды запуск выдаётся снова; повторный опрос не выдаёт взятый запуск (FR-3)
- [ ] Итог с вложением → в задаче комментарий и вложение; без вложений → один комментарий; обрыв стрима → пропущенные шаги досылаются по номерам, дублей нет (FR-4)
- [ ] Отмена → Harness остановлен, sandbox уничтожен; отмена завершённого запуска → статус не меняется; отмена при ожидании approve → `canceled`, запрос подтверждения закрыт (FR-7)
- [ ] Несовместимая версия протокола → Runner не забирает запуски и сообщает; совпадающая — запуски выдаются; необязательное поле от ICPlan игнорируется (FR-9)
- [ ] Runner не в сети → агенты «не в сети», запуски ждут; RustFS недоступно → итог публикуется без вложений, загрузка повторяется (FR-17)
- [ ] Запуск завершён → в M2 запись с итогом, статусом и токенами; ошибочный запуск → запись с причиной; БД ICPlan недоступна → итог досылается, M2 без дублей по `run_id` (FR-38)
- [ ] Запуск в очереди → Runner создаёт запись с `run_id` в `queued`; агент выключен или не найден → `agent_unavailable`, sandbox не создаётся; указана версия 3 при последней 5 → исполняется версия 3 (FR-66)
- [ ] Смена `queued` → `running` → событие в ICPlan; `gate_failed` → в ICPlan `failed` с пометкой «не прошёл проверку»; перезапуск Runner → статусы восстановлены из S3 без дублей (FR-72)
- [ ] Успешное завершение → `succeeded`, результат по `run_id`; результат не по формату → `gate_failed`; остановка по лимиту → частичный итог с пометкой «не завершено» (FR-73)
- [ ] Отмена в очереди → снят без создания sandbox; повторная отмена → статус не меняется, ошибки нет (FR-74)
- [ ] Репозиторий (write) и папка (read) в политике → манифест с обоими источниками уходит в Sandbox и `RunBundle`; нет политики → пустой манифест и событие; Platform module не ответил → запуск не стартует, «нет политики доступа» (FR-76)
- [ ] ICPlan недоступен → опрос с backoff, активные запуски идут, события буферизуются; Platform module недоступен → новые запуски не стартуют; Docker или пул недоступны → запуск остаётся в `queued`; Runner упал → запуски возвращаются в очередь, слоты свободны (FR-80)
- [ ] MCP-сервер недоступен → агент получает ошибку тула; шаг подготовки упал или превысил `setup.timeout_s` → `failed` с причиной «подготовка среды»; нет настроек агента или ключа → `agent_unavailable` (FR-80)
- [ ] Успешный запуск → Runner берёт его, создаёт запись с `run_id` и статусом `queued` (FR-66)
- [ ] Терминальный статус → итог с причиной отправлен в ICPlan, статус в ICPlan — `failed` с пометкой «не прошёл проверку» (FR-72)
- [ ] Выше максимума → значение отклонено, ошибка называет `scheduling.aging_s` и границы 60–3600 (FR-77)
- [ ] Граница от другого параметра → значение отклонено: `concurrency` не может быть больше `scheduling.global_max` (FR-77)
- [ ] Значение по умолчанию → применяется значение по умолчанию: 600 (FR-77)
- [ ] Аутентификация I2 → вызов не повторяется, событие с причиной (FR-79)
- [ ] Неидемпотентный вызов I6 → автоматического повтора нет, решение принимает вызывающий (FR-79)
- [ ] Таймаут I1 → вызов прерывается; повтор: backoff до 60 с (FR-79)
- [ ] Манифест собран → манифест содержит оба источника с правами и уходит в Sandbox и `RunBundle` (FR-76)
- [ ] Политика недоступна → запуск не стартует, причина «нет политики доступа» (FR-76)
- [ ] Платформа недоступна → запуск ждёт в очереди и исполняется после запуска Runner (FR-2)
- [ ] Минорное обновление → Runner продолжает работать, поле игнорируется (FR-9)
- [ ] Выше максимума → значение отклонено, ошибка называет `agent.delegation_delay_sec` и границы 0–86400 (FR-14)
- [ ] Значение по умолчанию → применяется значение по умолчанию: internal (FR-14)
- [ ] S1 недоступно → выдача запусков и приём итогов останавливаются; Runner повторяет с backoff, итог держит до восстановления (FR-15)
- [ ] Секрет в БД → в S1 попадает только шифротекст; из дампа БД без `APP_ENCRYPTION_KEY` ключ не прочитать (FR-15)
- [ ] Права по I20 → API ICPlan отклоняет запрос (403), данные не меняются, событие в журнале (FR-16)
- [ ] Таймаут I1 → вызов прерывается; повтор: backoff до 60 с (FR-16)
- [ ] Нет обязательного параметра → модуль не стартует, ошибка называет `protocol.version` (FR-14)
- [ ] Запись в своё хранилище → запись попадает в S1 (PostgreSQL 17 (CloudNativePG), БД `itsaplan`) (FR-15)

**Как прокликать:** ICPlan: агент «внешний» в сети → делегировать задачу → комментарий агента
