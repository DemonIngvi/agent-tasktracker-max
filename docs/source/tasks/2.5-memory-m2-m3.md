## Зачем

Агент следующего этапа должен продолжать работу, а не начинать с нуля. M3 — самый дешёвый способ дать это.

## Что сделать

- Хранилище M3 (состояние задачи)
- Тул записи M3 для агента
- Таблица `m4_fact` (M4, векторный поиск) создаётся после MVP вместе с RAG и в эту задачу не входит
- Подача M1 (последние сообщения треда `agent_chat_message`) в контекст
- Подача M3 и итогов последних N запусков (M2) в контекст
- Проверки записи по уровням: профиль, область, схема и размер M3, секреты, идемпотентность M2
- Управление памятью: администратор просматривает, правит, удаляет M1–M3 (M4 — бэклог, вместе с RAG)
- M5 (инструкция, навыки) подаётся задачей [2.3](2.3-config-from-icplan.md), M6 (`get_document`) — задачей [2.4](2.4-mcp-itsaplan-core.md)
- Срок памяти M1 и M2 — фильтр чтения по `retention` профиля: [Memory](../../architecture/components/memory/README.md) не отдаёт записи старше срока и не удаляет строки форка; `POST /retention/run` удаляет только M3 ([AD-25](..\design\define-agent-platform\design.md), [R&D](..\..\research\fork-run-retention.md))

## Приёмка

- [ ] Агент записал M3 → следующий агент видит его в контексте
- [ ] Итоги прошлых запусков в контексте
- [ ] В треде задачи есть сообщения → последние попадают в контекст (M1); тред пуст → раздел пуст ([FR-36](../../architecture/components/memory/prd.md))
- [ ] Итог запуска старше срока M2 профиля не попадает в контекст, строка `agent_run` остаётся ([FR-43](../../architecture/components/memory/prd.md), [AD-25](../../architecture/decisions/AD-25.yaml))
- [ ] Завершение запуска → M0 уничтожается вместе с sandbox, M1–M6 сохраняются; неизвестный уровень в профиле → профиль не сохраняется, ошибка валидации ([FR-36](../../architecture/components/memory/prd.md))
- [ ] Агент B берёт задачу после агента A → контекст B содержит M3 агента A; M3 ещё нет → контекст без M3; два запуска пишут M3 одновременно → сохраняется последняя версия, прежняя в истории ([FR-39](../../architecture/components/memory/prd.md))
- [ ] У задачи 10 запусков, N = 3 → в контекст попадают итоги трёх последних; задача запускается впервые → раздел истории пуст ([FR-40](../../architecture/components/memory/prd.md))
- [ ] Администратор удаляет запись M3 → следующие запуски её не получают; исправляет запись M3 → следующий запуск получает исправленную; участник без права удаляет → отказ в доступе ([FR-42](../../architecture/components/memory/prd.md))
- [ ] Агент пишет в M3 запись с токеном → отклонено, причина «секрет в записи»; запись M3 больше `m3_max_kb` → отклонено с границей в причине; профиль записи «нет» → «уровень не разрешён профилем»; повтор итога с тем же `run_id` → в M2 одна запись ([FR-44](../../architecture/components/memory/prd.md))
- [ ] БД недоступна → чтение отдаёт пустой контекст с предупреждением, запись повторяется; очистка M3 не прошла → записи остаются, M3 закрытых задач не отдаётся в контекст, уведомление эксплуатации; профиль памяти не задан → значения по умолчанию ([FR-51](../../architecture/components/memory/prd.md))
- [ ] Конфликт записи → сохраняется последняя версия, предыдущая остаётся в истории ([FR-39](../../architecture/components/memory/prd.md))
- [ ] Следующий этап → контекст B содержит M3, записанное A ([FR-39](../../architecture/components/memory/prd.md))
- [ ] Запусков больше N → в контекст попадают итоги трёх последних ([FR-40](../../architecture/components/memory/prd.md))
- [ ] Повторный запуск → видит итоги прошлых запусков ([FR-40](../../architecture/components/memory/prd.md))
- [ ] Удаление ошибочного факта → последующие запуски её не получают ([FR-42](../../architecture/components/memory/prd.md))
- [ ] Истёк срок → запись недоступна для чтения ([FR-43](../../architecture/components/memory/prd.md))
- [ ] Сбой очистки → записи остаются, задание CronJob помечено неуспешным и повторяется; неуспешное задание поднимает уведомление эксплуатации ([FR-43](../../architecture/components/memory/prd.md))
- [ ] Срок не истёк → запись доступна ([FR-43](../../architecture/components/memory/prd.md))
- [ ] Удаление в журнале → ответ `{deleted: {m3}}` и запись в журнале [Memory](../../architecture/components/memory/README.md) API: сколько записей и по какому сроку удалено ([FR-43](../../architecture/components/memory/prd.md))
- [ ] Выше максимума → значение отклонено, ошибка называет `m3_max_kb` и границы 2–64 ([FR-48](../../architecture/components/memory/prd.md))
- [ ] Ниже минимума → значение отклонено, ошибка называет `m2_last_runs` и границы 0–10 ([FR-48](../../architecture/components/memory/prd.md))
- [ ] S4 недоступно → чтение — пустой контекст с предупреждением; запись — повтор ([FR-49](../../architecture/components/memory/prd.md))
- [ ] Аутентификация [I2](../../architecture/components/agent-runner/integrations/I2.yaml) → вызов не повторяется, событие с причиной ([FR-50](../../architecture/components/memory/prd.md))
- [ ] Повтор [I2](../../architecture/components/agent-runner/integrations/I2.yaml) без дублей → дубля нет: да, по (run_id, seq) ([FR-50](../../architecture/components/memory/prd.md))
- [ ] Таймаут [I11](../../architecture/components/harness/integrations/I11.yaml) → вызов прерывается; повтор: 2 раза ([FR-50](../../architecture/components/memory/prd.md))
- [ ] Значение по умолчанию → применяется значение по умолчанию: 16 ([FR-48](../../architecture/components/memory/prd.md))

**Как прокликать:** Два агента по одной задаче: второй ссылается на то, что сделал первый
