## Зачем

Пользователь настраивает агента в UI ICPlan; Harness должен брать модель, инструкцию и тулы оттуда, а недостающее (лимиты, approve) — из YAML до появления Platform module.

## Что сделать

- Чтение определения агента у Platform module: `GET /platform/runs/:runId/agent` → `{version, definition, settings}` (I4, AD-23, R&D)
- Минимальный Platform module: этот эндпоинт и сервисный токен Runner; версия запуска — в `agent_run.agent_version` при первом вызове
- Дополнения (лимиты, approve) — настройки Platform module `agent_settings`, отдельного файла YAML нет; YAML загружается импортом `POST /platform/agents/import` с проверкой ссылок на ресурсы по БД (AD-26)
- Версии агента в MVP (FR-55, решение владельца 2026-10-14): таблица `agent_settings_version`, новая версия по хешу определения при вызове I4 (AD-26), поле `Run.settingsVersionId` — запуск на указанной версии, несуществующая — отказ
- Перенос алиаса модели на LiteLLM
- Тулы, навыки, MCP-серверы агента (MCP — `project_resource` и `access_policy`, AD-23) и критерии приёмки задачи (L3) из ICPlan в `RunBundle`

## Приёмка

- [ ] Изменить `agent.model` или инструкцию агента в ICPlan во время запуска → активный запуск на старой, следующий — на новой (FR-59 «Изменение настройки»)
- [ ] Сменить модель агента и вернуть прежнюю → новые запуски на новой, затем на прежней; модель, не настроенная в LiteLLM, отклонена (FR-58 «Замена модели», «Модель без доступа», «Откат модели»)
- [ ] Сохранить агента без `agent.model` → отказ, ошибка называет `agent.model` (FR-59 «Нет обязательного поля», FR-54 «Обязательное поле отсутствует»)
- [ ] Выключить агента (`agent.enabled = false`) → в списке «выключен», делегирование отклонено с причиной (FR-8 «Агент выключен», FR-54 «Выключение агента»)
- [ ] Остановить Runner дольше порога → агенты платформы «не в сети»; запустить → «в сети» (FR-8)
- [ ] БД ICPlan недоступна → определения не читаются, запуски не стартуют (FR-60 «S1 недоступно», FR-62 «БД ICPlan недоступна»)
- [ ] Пользователь без права меняет определение → 403, данные не меняются (FR-61 «Права по I20»)
- [ ] Импортировать YAML с лимитами → лимиты в `agent_settings`, следующий запуск получает их в `RunBundle.params` (FR-56, AD-26); импорт со ссылкой на несуществующий навык → отказ с указанием ссылки (FR-57 «Битая ссылка»)
- [ ] Запуск, ждущий слота, после правки агента стартует с новой версией; повторная выдача запуска получает ту же версию (`agent_run.agent_version`, AD-23)
- [ ] Запрос определения по запуску не в `pending` или агента не `external` → 404; версии нет → 409 (AD-23)
- [ ] Завершить запуск → рабочая память M0 уничтожена с sandbox, M1–M6 сохранены; инструкция и навыки агента (M5) поданы в `RunBundle` из ICPlan; профиль с несуществующим уровнем памяти не сохраняется, ошибка валидации (FR-36 «Завершение запуска», «Неизвестный уровень»)
- [ ] Шлюз недоступен → смена модели не сохраняется, администратор видит причину «проверить модель нельзя»; правка без смены модели сохраняется (FR-58)
- [ ] Значение по умолчанию → применяется значение по умолчанию: нет (FR-59)
- [ ] Повтор I1 без дублей → дубля нет: аренда: выдаётся одному Runner (FR-61)
- [ ] Таймаут I1 → вызов прерывается; повтор: backoff до 60 с (FR-61)
- [ ] Импорт с неверной схемой → импорт отклоняется (FR-62)
- [ ] Удалён ресурс, на который ссылаются → удаление отклоняется (FR-62)
- [ ] Запуск с `settingsVersionId` = 2 при актуальной версии 3 → Runner получает определение версии 2, `agent_run.agent_version = 2`, повторная выдача — та же (FR-55 «Запуск на прежней версии»)
- [ ] Изменить инструкцию агента → создаётся версия 4, версии 1–3 читаются (FR-55 «Новая версия»)
- [ ] Запуск с `settingsVersionId`, которой нет → запуск отклонён с ошибкой версии (409), `agent_run` не получает версию (FR-55 «Несуществующая версия»)

**Как прокликать:** ICPlan: поменять инструкцию агента → делегировать → ответ по новой инструкции
