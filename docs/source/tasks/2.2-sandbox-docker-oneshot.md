## Зачем

Изоляция запусков с первого дня интеграции; тёплый пул — оптимизация позже (4.1).

## Что сделать

- Образ [Harness](../../architecture/components/harness/README.md)
- `SandboxProvider` (Docker): create / exec / destroy
- Эфемерный `/workspace`
- Лимиты CPU/RAM из профиля
- Подключение источников манифеста: git-клон и папка из объектного хранилища, выгрузка своей подпапки

## Приёмка

- [ ] После запуска контейнера нет
- [ ] Два параллельных запуска не видят файлы друг друга
- [ ] Лимит RAM применяется
- [ ] Запуск `failed` или `succeeded` → sandbox уничтожен, логи сохранены; контейнер не удалился → Runner повторяет удаление и пишет событие, слот не занят ([FR-75](../../architecture/components/agent-runner/prd.md))
- [ ] Агент с профилем увеличенной RAM → sandbox с этой RAM; превышение RAM → контейнер остановлен, `failed` с причиной; профиль не найден или `runtime: runsc` без runsc на узле → запуск отклонён до создания контейнера ([FR-86](../../architecture/components/sandbox/prd.md))
- [ ] Репозиторий (write) и папка (read) в манифесте → клон в `/workspace/repo`, папка в `/workspace/task`, запись только в репозиторий; подпапка шага выгружена новой версией; запись в папку с правом read отклонена ([FR-89](../../architecture/components/sandbox/prd.md))
- [ ] Нет `setup.script`-кэша → шаг подготовки в контейнере с `setup.registries`, результат в `/workspace/.deps`; lock-файлы не менялись и кэш свежий → шаг пропущен ([FR-89](../../architecture/components/sandbox/prd.md))
- [ ] Нет ресурсов хоста → запуск ждёт в `queued`; образ недоступен → профиль помечен недоступным; диск workspace переполнен → запись отклонена; реестр пакетов или RustFS недоступны → ошибка подготовки или «нет рабочего пространства» ([FR-93](../../architecture/components/sandbox/prd.md))
- [ ] `docker compose` поднимает [ICPlan](../../architecture/components/icplan/README.md), Postgres, RustFS, LiteLLM с mock → [Harness](../../architecture/components/harness/README.md) разрабатывается локально; версия образа в compose отличается от чарта → проверка сообщает о расхождении ([FR-169](../../architecture/components/infrastructure/prd.md))
- [ ] Проверка gVisor 2.2.8 выполнена, результат записан в R&D изоляции и TECHNOLOGIES
- [ ] Ошибка уничтожения → Runner повторяет удаление и пишет событие; слот не занимается ([FR-75](../../architecture/components/agent-runner/prd.md))
- [ ] Падение агента → sandbox уничтожен, логи и трейсы сохранены в [Observability](../../architecture/components/observability/README.md) ([FR-75](../../architecture/components/agent-runner/prd.md))
- [ ] Успешное завершение → sandbox уничтожен, пул долит ([FR-75](../../architecture/components/agent-runner/prd.md))
- [ ] Повторное использование запрещено → он уничтожается, а не возвращается в пул ([FR-82](../../architecture/components/sandbox/prd.md))
- [ ] Превышение памяти → контейнер останавливается, запуск получает `failed` с причиной ([FR-86](../../architecture/components/sandbox/prd.md))
- [ ] Тяжёлый агент → его sandbox создаётся с этой RAM ([FR-86](../../architecture/components/sandbox/prd.md))
- [ ] Граница от другого параметра → значение отклонено: `pool.size` не может быть больше `scheduling.global_max` ([FR-90](../../architecture/components/sandbox/prd.md))
- [ ] Значение по умолчанию → применяется значение по умолчанию: нет ([FR-90](../../architecture/components/sandbox/prd.md))
- [ ] Недопустимое значение → значение отклонено, ошибка называет `resources` и допустимые значения ([FR-90](../../architecture/components/sandbox/prd.md))
- [ ] S10 переполнен → запись отклоняется, агент получает ошибку тула, запуск продолжается или завершается `limit` ([FR-91](../../architecture/components/sandbox/prd.md))
- [ ] Выделение диска → у среды свой `/workspace` размером по профилю, чужих томов нет ([FR-91](../../architecture/components/sandbox/prd.md))
- [ ] Аутентификация [I7](../../architecture/components/agent-runner/integrations/I7.yaml) → вызов не повторяется, событие с причиной ([FR-92](../../architecture/components/sandbox/prd.md))
- [ ] Неидемпотентный вызов [I6](../../architecture/components/agent-runner/integrations/I6.yaml) → автоматического повтора нет, решение принимает вызывающий ([FR-92](../../architecture/components/sandbox/prd.md))
- [ ] Таймаут [I6](../../architecture/components/agent-runner/integrations/I6.yaml) → вызов прерывается; повтор: 1 раз ([FR-92](../../architecture/components/sandbox/prd.md))
- [ ] Egress-прокси упал → исходящий трафик запрещён (fail-closed) ([FR-93](../../architecture/components/sandbox/prd.md))
- [ ] Нет права записи → запись отклонена, выгрузки нет ([FR-89](../../architecture/components/sandbox/prd.md))
- [ ] Проверка чартов → результат совпадает с серверной установкой, кроме адресов и ресурсов ([FR-169](../../architecture/components/infrastructure/prd.md))
- [ ] Последовательные запуски одного агента → второй запуск получает новый контейнер без файлов первого ([FR-82](../../architecture/components/sandbox/prd.md))
- [ ] Уничтожение → диск `/workspace` удалён вместе со средой, данные не переходят в следующий запуск ([FR-91](../../architecture/components/sandbox/prd.md))
- [ ] Два параллельных запуска → у запусков разные sandbox и они не видят файлы друг друга ([FR-82](../../architecture/components/sandbox/prd.md))

**Как прокликать:** Делегировать 2 задачи подряд → `docker ps` пуст после завершения, ответы в задачах
