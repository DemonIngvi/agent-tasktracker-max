## Зачем

Платформа должна разворачиваться воспроизводимо на сервере: кластер, чарты, вход по HTTPS, изоляция namespaces, секреты вне git.

## Что сделать

- k3s на узле, namespaces `itsaplan-core`, `itsaplan-data`, `itsaplan-agents`
- Чарты: `itsaplan` (форк), `litellm`, `agent-platform` (Runner, OPA, Memory, egress)
- Traefik Ingress: HTTPS, ACME, маршруты web / api / mcp; админки без ingress
- NetworkPolicy по списку интерфейсов I1–I23
- Secret через `existingSecret`, скрипт создания из `.env`
- Проверки liveness / readiness, порядок запуска
- Провайдер сред запуска в K8s (I23) и CIS-проверка узла

## Приёмка

- [ ] Установка с нуля проходит скриптом
- [ ] Админки недоступны снаружи (404)
- [ ] Контейнер запуска не достучится до Postgres
- [ ] Обновление чарта LiteLLM без простоя
- [ ] Установка на чистом сервере → k3s, namespaces, все сервисы готовы; повторная установка → изменения без пересоздания данных; сервис агента создаёт объект в `itsaplan-core` → отказ правами ServiceAccount (FR-159)
- [ ] Обновление чарта LiteLLM → реплики заменяются по одной, вызовы не прерываются; версия не прошла проверки готовности → откат на предыдущую ревизию; секрет в `values.yaml` → установка отклонена проверкой чарта (FR-160)
- [ ] Пользователь открывает адрес ICPlan → HTTPS через Traefik к `web`; запрос на адрес LiteLLM снаружи → 404; HTTP → перенаправление на HTTPS (FR-161)
- [ ] Одна из двух реплик LiteLLM не прошла readiness → трафик на здоровую; обе реплики OPA готовы → запросы распределяются; нет готовых реплик → клиенты получают ошибку соединения (FR-162)
- [ ] Добавлен ключ провайдера → попадает в Secret, сервис перечитывает без пересборки; значение секрета в коммите → останавливает проверка перед коммитом; обязательного Secret нет → сервис не стартует, ошибка называет Secret (FR-166)
- [ ] Runner обращается к API ICPlan → разрешено; контейнер запуска подключается к Postgres напрямую → заблокировано; новый интерфейс в `interfaces.md` → политика дополнена до выпуска (FR-167)
- [ ] Холодный старт → сначала Postgres и PgBouncer, затем api, LiteLLM, OPA, затем Runner; Postgres пропал у работающего api → api не готов, ingress не шлёт трафик; процесс не отвечает на liveness → под перезапущен (FR-168)
- [ ] compose поднимает ICPlan, Postgres, RustFS, LiteLLM с mock; чарты в k3d дают тот же результат, что на сервере, кроме адресов и ресурсов; версия образа в compose отличается от чарта → проверка согласованности сообщает о расхождении (FR-169)
- [ ] Установка платформы → компоненты подняты в порядке проверок готовности; обновление чарта компонента → замена по одной реплике, проверки зелёные; узлу не хватает ресурсов → под ждёт размещения, предупреждение эксплуатации (FR-174)
- [ ] Новый образ Harness (`HARNESS_IMAGE`) → новые запуски на нём, активные доделываются; образ не скачивается → запуск `failed` с причиной «образ недоступен»; не хватает ресурсов → запуск ждёт в `queued` (FR-35)
- [ ] Новый образ среды → пул пересоздаёт тёплые контейнеры; новая версия `egress-proxy` → замена без разрыва соединений дольше переподключения; не хватает ресурсов → запуск ждёт в `queued`, пул не доливается (FR-94)
- [ ] Обновление api ICPlan с `itsaplan-core` → MCP обновляется по одной реплике; новый внешний MCP-сервер → образ закреплён по digest, доступ через egress-прокси; сервер не прошёл готовность → его тулы недоступны, остальные работают (FR-187)
- [ ] Нехватка ресурсов → запуск ждёт в `queued` до освобождения слотов (FR-35)
- [ ] Нехватка ресурсов → под `memory-api` ждёт размещения, событие эксплуатации (FR-52)
- [ ] Нехватка ресурсов → под `agent-runner` ждёт размещения, событие эксплуатации (FR-81)
- [ ] Нехватка ресурсов → запуск ждёт в `queued`, тёплый пул не доливается до освобождения ресурсов (FR-94)
- [ ] Нехватка ресурсов → под `opa` ждёт размещения, событие эксплуатации (FR-130)
- [ ] Нехватка ресурсов → под `litellm` ждёт размещения, событие эксплуатации (FR-145)
- [ ] Защита узла → критичных несоответствий CIS нет (FR-159)
- [ ] Ресурс в чужом namespace → операция отклонена правами ServiceAccount (FR-159)
- [ ] Развёртывание dev/CI/staging/prod → отдельные namespaces, базы и Secrets; workload пытается обратиться к БД или Secret другой среды → доступ отклонён; манифест ссылается на ресурс другой среды → проверка отклоняет развёртывание (FR-175)
- [ ] Попытка открыть админку → маршрута нет, ответ 404 (FR-161)
- [ ] Новый секрет → он попадает в Secret, сервис перечитывает его без пересборки образа (FR-166)

- [ ] Запрещённый маршрут → соединение блокируется (FR-167)
- [ ] Зависимость пропала → api перестаёт быть готовым, ingress не шлёт на него трафик (FR-168)
- [ ] Зависший процесс → под перезапускается (FR-168)
- [ ] Значение вне схемы → `helm upgrade` отклонён схемой с именем параметра и границей (FR-170)
- [ ] Аутентификация I22 → вызов не повторяется, событие с причиной (FR-172)
- [ ] Таймаут I21 → вызов прерывается; повтор: нет (FR-172)
- [ ] Нехватка ёмкости → под ждёт размещения, предупреждение эксплуатации (FR-174)
- [ ] Версия не закреплена → установка отклонена: версия обязательна (FR-170)
- [ ] Установка с нуля → k3s установлен, namespaces созданы, все сервисы готовы (FR-159)
