## Зачем

Платформа должна разворачиваться воспроизводимо на сервере: кластер, чарты, вход по HTTPS, изоляция namespaces, секреты вне git.

## Что сделать

- k3s на узле, namespaces `itsaplan-core`, `itsaplan-data`, `itsaplan-agents`
- Чарты: `itsaplan` (форк), `litellm`, `agent-platform` (Runner, OPA, [Memory](../../architecture/components/memory/README.md), egress)
- Traefik Ingress: HTTPS, ACME, маршруты web / api / mcp; админки без ingress
- NetworkPolicy по списку интерфейсов [I1](../../architecture/components/agent-runner/integrations/I1.yaml)–[I23](../../architecture/components/agent-runner/integrations/I23.yaml)
- Secret через `existingSecret`, скрипт создания из `.env`
- Проверки liveness / readiness, порядок запуска
- Провайдер сред запуска в K8s ([I23](../../architecture/components/agent-runner/integrations/I23.yaml)) и CIS-проверка узла

## Приёмка

- [ ] Установка с нуля проходит скриптом
- [ ] Админки недоступны снаружи (404)
- [ ] Контейнер запуска не достучится до Postgres
- [ ] Обновление чарта LiteLLM без простоя
- [ ] Установка на чистом сервере → k3s, namespaces, все сервисы готовы; повторная установка → изменения без пересоздания данных; сервис агента создаёт объект в `itsaplan-core` → отказ правами ServiceAccount ([FR-159](../../architecture/components/infrastructure/prd.md))
- [ ] Обновление чарта LiteLLM → реплики заменяются по одной, вызовы не прерываются; версия не прошла проверки готовности → откат на предыдущую ревизию; секрет в `values.yaml` → установка отклонена проверкой чарта ([FR-160](../../architecture/components/infrastructure/prd.md))
- [ ] Пользователь открывает адрес [ICPlan](../../architecture/components/icplan/README.md) → HTTPS через Traefik к `web`; запрос на адрес LiteLLM снаружи → 404; HTTP → перенаправление на HTTPS ([FR-161](../../architecture/components/infrastructure/prd.md))
- [ ] Одна из двух реплик LiteLLM не прошла readiness → трафик на здоровую; обе реплики OPA готовы → запросы распределяются; нет готовых реплик → клиенты получают ошибку соединения ([FR-162](../../architecture/components/infrastructure/prd.md))
- [ ] Добавлен ключ провайдера → попадает в Secret, сервис перечитывает без пересборки; значение секрета в коммите → останавливает проверка перед коммитом; обязательного Secret нет → сервис не стартует, ошибка называет Secret ([FR-166](../../architecture/components/infrastructure/prd.md))
- [ ] Runner обращается к API [ICPlan](../../architecture/components/icplan/README.md) → разрешено; контейнер запуска подключается к Postgres напрямую → заблокировано; новый интерфейс в `interfaces.md` → политика дополнена до выпуска ([FR-167](../../architecture/components/infrastructure/prd.md))
- [ ] Холодный старт → сначала Postgres и PgBouncer, затем api, LiteLLM, OPA, затем Runner; Postgres пропал у работающего api → api не готов, ingress не шлёт трафик; процесс не отвечает на liveness → под перезапущен ([FR-168](../../architecture/components/infrastructure/prd.md))
- [ ] compose поднимает [ICPlan](../../architecture/components/icplan/README.md), Postgres, RustFS, LiteLLM с mock; чарты в k3d дают тот же результат, что на сервере, кроме адресов и ресурсов; версия образа в compose отличается от чарта → проверка согласованности сообщает о расхождении ([FR-169](../../architecture/components/infrastructure/prd.md))
- [ ] Установка платформы → компоненты подняты в порядке проверок готовности; обновление чарта компонента → замена по одной реплике, проверки зелёные; узлу не хватает ресурсов → под ждёт размещения, предупреждение эксплуатации ([FR-174](../../architecture/components/infrastructure/prd.md))
- [ ] Новый образ [Harness](../../architecture/components/harness/README.md) (`HARNESS_IMAGE`) → новые запуски на нём, активные доделываются; образ не скачивается → запуск `failed` с причиной «образ недоступен»; не хватает ресурсов → запуск ждёт в `queued` ([FR-35](../../architecture/components/harness/prd.md))
- [ ] Новый образ среды → пул пересоздаёт тёплые контейнеры; новая версия `egress-proxy` → замена без разрыва соединений дольше переподключения; не хватает ресурсов → запуск ждёт в `queued`, пул не доливается ([FR-94](../../architecture/components/sandbox/prd.md))
- [ ] Обновление api [ICPlan](../../architecture/components/icplan/README.md) с `itsaplan-core` → MCP обновляется по одной реплике; новый внешний MCP-сервер → образ закреплён по digest, доступ через egress-прокси; сервер не прошёл готовность → его тулы недоступны, остальные работают ([FR-187](../../architecture/components/mcp-tools/prd.md))
- [ ] Нехватка ресурсов → запуск ждёт в `queued` до освобождения слотов ([FR-35](../../architecture/components/harness/prd.md))
- [ ] Нехватка ресурсов → под `memory-api` ждёт размещения, событие эксплуатации ([FR-52](../../architecture/components/memory/prd.md))
- [ ] Нехватка ресурсов → под `agent-runner` ждёт размещения, событие эксплуатации ([FR-81](../../architecture/components/agent-runner/prd.md))
- [ ] Нехватка ресурсов → запуск ждёт в `queued`, тёплый пул не доливается до освобождения ресурсов ([FR-94](../../architecture/components/sandbox/prd.md))
- [ ] Нехватка ресурсов → под `opa` ждёт размещения, событие эксплуатации ([FR-130](../../architecture/components/guardrails/prd.md))
- [ ] Нехватка ресурсов → под `litellm` ждёт размещения, событие эксплуатации ([FR-145](../../architecture/components/llm-gateway/prd.md))
- [ ] Защита узла → критичных несоответствий CIS нет ([FR-159](../../architecture/components/infrastructure/prd.md))
- [ ] Ресурс в чужом namespace → операция отклонена правами ServiceAccount ([FR-159](../../architecture/components/infrastructure/prd.md))
- [ ] Развёртывание dev/CI/staging/prod → отдельные namespaces, базы и Secrets; workload пытается обратиться к БД или Secret другой среды → доступ отклонён; манифест ссылается на ресурс другой среды → проверка отклоняет развёртывание ([FR-175](../../architecture/components/infrastructure/prd.md))
- [ ] Попытка открыть админку → маршрута нет, ответ 404 ([FR-161](../../architecture/components/infrastructure/prd.md))
- [ ] Новый секрет → он попадает в Secret, сервис перечитывает его без пересборки образа ([FR-166](../../architecture/components/infrastructure/prd.md))
- [ ] Секрет в репозитории → проверка перед коммитом его останавливает ([FR-166](../../architecture/components/infrastructure/prd.md))
- [ ] Запрещённый маршрут → соединение блокируется ([FR-167](../../architecture/components/infrastructure/prd.md))
- [ ] Зависимость пропала → api перестаёт быть готовым, ingress не шлёт на него трафик ([FR-168](../../architecture/components/infrastructure/prd.md))
- [ ] Зависший процесс → под перезапускается ([FR-168](../../architecture/components/infrastructure/prd.md))
- [ ] Значение вне схемы → `helm upgrade` отклонён схемой с именем параметра и границей ([FR-170](../../architecture/components/infrastructure/prd.md))
- [ ] Аутентификация [I22](../../architecture/integrations/I22.yaml) → вызов не повторяется, событие с причиной ([FR-172](../../architecture/components/infrastructure/prd.md))
- [ ] Таймаут [I21](../../architecture/integrations/I21.yaml) → вызов прерывается; повтор: нет ([FR-172](../../architecture/components/infrastructure/prd.md))
- [ ] Нехватка ёмкости → под ждёт размещения, предупреждение эксплуатации ([FR-174](../../architecture/components/infrastructure/prd.md))
- [ ] Версия не закреплена → установка отклонена: версия обязательна ([FR-170](../../architecture/components/infrastructure/prd.md))
- [ ] Установка с нуля → k3s установлен, namespaces созданы, все сервисы готовы ([FR-159](../../architecture/components/infrastructure/prd.md))
