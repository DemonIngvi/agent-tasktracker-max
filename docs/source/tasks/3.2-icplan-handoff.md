## Зачем

Следующий агент должен получать итог предыдущего, а пользователь — понимать, почему агент начал работу.

## Что сделать

- Передача по контракту шага (AD-20): M3, ссылки на артефакты, предложенные критерии; ссылка на итог
- Запись «агент взял задачу по правилу…» в истории

## Приёмка

- [ ] Процесс из двух шагов с агентами A и B: шаг A успешен → задача на шаге B, задание B содержит ссылку на итог A (FR-193 «Смена агента»)
- [ ] Задача на первом шаге без прошлых запусков → задание без ссылки на итог; последний запуск упал → ссылка на итог с пометкой ошибки (FR-193 «Первый этап», «Предыдущий запуск упал»)
- [ ] Агент шага A предложил критерий шагу B с `criteria_approval: auto` → критерий у задачи с пометкой «предложено: A» и действует для B; при `review` или проверке шага — ждёт подтверждения до старта B (FR-193 «Критерии от предыдущего шага», «Подтверждение на шаге с проверкой»)
- [ ] Итог без обязательного раздела, повторы исчерпаны → `gate_failed` с перечнем; без критериев → «gate не задан» (FR-26 «Gate не пройден», «Критериев нет»)
- [ ] Агент шага пытается изменить критерий своего шага → отказ, событие с причиной (FR-26 «Попытка ослабить критерий»)
- [ ] История задачи: «Агент Y взял задачу: процесс …, шаг …», «Итог: успех → шаг …»; ручное делегирование — «делегировано пользователем» (FR-194)
- [ ] Переход по итогу → в истории «Итог: успех → шаг "Спецификация"» (FR-194)
- [ ] Разбор → видит «Агент Y взял задачу: процесс "Фича", шаг "Анализ"» (FR-194)

**Как прокликать:** Процесс «Фича» из двух шагов с агентами → создать задачу → задача сама проходит оба шага, в истории видны правила подхвата и переход
