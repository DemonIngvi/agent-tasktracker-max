## Зачем

Пауза на approve из 1.5 должна управляться из задачи ICPlan, иначе опасные действия блокируют работу.

## Что сделать

- Событие «нужен approve» в задаче
- Кнопки одобрить / отклонить: право `work_items.edit` в проекте задачи (роли форка, AD-26)
- Передача ответа в Runner → Harness
- Вопрос агента (ожидание ответа) и ответ пользователя в задаче

## Приёмка

- [ ] Агент R2 вызвал опасный тул → запуск на паузе, в задаче запрос с кнопками; «одобрить» → действие выполнено, запуск продолжается (FR-117 «Агент R2», FR-5 «Подтверждение действия»)
- [ ] «Отклонить» → агент получает отказ, продолжает без действия или завершает запуск (FR-5 «Отказ»)
- [ ] Участник без права `work_items.edit` в проекте задачи нажимает «одобрить» → `POST /agent-runs/:runId/decisions` отвечает 403, кнопок у него нет, запрос открыт (FR-5 «Нет прав на подтверждение», AD-26)
- [ ] Решение по уже завершённому запуску или повторное решение по тому же `seq` → 409, в ленте одно решение (FR-5; ошибки `POST /agent-runs/:runId/decisions`)
- [ ] Запрос подтверждения → исполнитель получает уведомление со ссылкой и сроком; без исполнителя — участники с правом `work_items.edit` в проекте; до истечения интервала повтора второго уведомления нет (FR-6)
- [ ] Решения нет дольше `guardrails.approval_timeout` → отказ и запись в ленте (FR-23 «Истёк таймаут ожидания»)
- [ ] Агент R4 делает опасное обратимое действие → без паузы, запись в аудите; агент R5 на релизе в prod → пауза на подтверждение (FR-117 «Агент R4», «Релиз в prod»)
- [ ] Агент задал вопрос (`CUSTOM` `question`) → пользователь ответил в задаче → агент продолжил с ответом (FR-5 «запрос… или вопрос», FR-23 «пауза на вопрос пользователю»)

**Как прокликать:** Задача с опасным действием: нажать «одобрить» в ICPlan

## Декомпозиция

Подзадачи по 2–8 часов; каждая проверяема сама по себе.

| # | Подзадача | Человек, ч | Готово, когда |
|---|---|---|---|
| 3.4.1 | Событие `CUSTOM` `approval_request` в ленте задачи и уведомление | 6 | пользователь видит запрос |
| 3.4.2 | UI: кнопки одобрить / отклонить; проверка права `work_items.edit` в API (403) и в UI (AD-26) | 8 | кнопки работают по праву, без права — 403 |
| 3.4.3 | Передача решения в Runner → Harness: таблица `agent_run_delivery` (миграция), доставка через heartbeat | 6 | агент продолжает после одобрения |
| 3.4.4 | Таймаут ожидания `guardrails.approval_timeout` | 3 | по таймауту — отказ и запись |
| 3.4.5 | E2E | 5 | сценарий зелёный |
| 3.4.6 | Событие `CUSTOM` `question` (вопрос агента) и ответ пользователя (`ApprovalDecision` `answer`) → Runner | 4 | агент продолжает после ответа |
| | **Итого** | **32 ч ≈ 4 дн** | |
