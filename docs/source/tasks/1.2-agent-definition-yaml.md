## Зачем

Формат YAML — контракт между [ICPlan](../../architecture/components/icplan/README.md), [Harness](../../architecture/components/harness/README.md) и экспортом/импортом. Зафиксировав его первым, мы делаем [Harness](../../architecture/components/harness/README.md) сейчас, а в [ICPlan](../../architecture/components/icplan/README.md) потом переносим тот же формат без переделок.

## Что сделать

- Схема (JSON Schema) по модели [`AgentDefinition`](../../architecture/data/model-AgentDefinition.yaml) (`agent/v1`): поля Registry — `apiVersion`, `id`, `version`, `model` (алиас LiteLLM), `instructions`, `skills`, `mcp` (`{server, tools[]}` — allowlist тулов); поля [Platform module](../../architecture/components/platform-module/README.md) ([FR-54](../../architecture/components/platform-module/prd.md), хранятся в [`AgentSettings`](../../architecture/data/model-AgentSettings.yaml), в YAML — при экспорте и импорте) — `limits`, `approval`, `memory`, `sandbox`
- Офлайн-валидатор: схема `agent/v1` и внутренние ссылки файла (тул в `approval` есть в `mcp.tools`); ссылки на ресурсы (навыки, тулы, MCP, профили) проверяет импорт [Platform module](../../architecture/components/platform-module/README.md) `POST /platform/agents/import` по БД — задача [2.3](2.3-config-from-icplan.md) ([AD-26](..\design\define-agent-platform\design.md))
- Навык — формат Anthropic Agent Skill: `SKILL.md` с frontmatter `name`, `description`, справочные файлы, без исполняемых скриптов (как в форке, `skill-format.ts`; [AD-26](..\design\define-agent-platform\design.md))
- 2 примера: агент-аналитик (без тулов записи), агент с MCP и approve на опасном туле
- Документ формата с примерами

## Приёмка

- [ ] Два примера прогнать через валидатор → оба проходят ([FR-57](../../architecture/components/platform-module/prd.md) «Все ссылки верны»)
- [ ] Определение без `model` → отказ, ошибка называет поле ([FR-54](../../architecture/components/platform-module/prd.md) «Обязательное поле отсутствует»)
- [ ] Битая внутренняя ссылка (тул в `approval`, которого нет в `mcp.tools`) → отказ с указанием ссылки ([FR-57](../../architecture/components/platform-module/prd.md) «Битая ссылка»); ссылку на навык, которого нет в БД, отклоняет импорт (2.3)
- [ ] Навык примера без frontmatter `name` или со скриптом → отказ (формат навыка, [AD-26](../../architecture/decisions/AD-26.yaml))
- [ ] Ресурс с неподдерживаемым типом или повторным `id` в файле определения → отказ, у типа — перечень допустимых ([FR-53](../../architecture/components/platform-module/prd.md) «Неизвестный тип», «Дубликат»)
- [ ] `model.temperature` > 1.0 или `limits.max_tokens` выше потолка `budget.per_run_tokens` → отказ с именем параметра и границами ([FR-31](../../architecture/components/harness/prd.md) «Выше максимума», «Граница от другого параметра»)
- [ ] Без `model.temperature` → в итоговых параметрах 0.2 ([FR-31](../../architecture/components/harness/prd.md) «Значение по умолчанию»)
- [ ] Поля, которые [Harness](../../architecture/components/harness/README.md) читает из `RunBundle.agent` (`agentId` ← `id`, `model`, `version`, `instructions`, `skills`), есть в схеме
- [ ] Регистрация ресурса → ресурс получает идентификатор и версию и становится доступен для ссылок ([FR-53](../../architecture/components/platform-module/prd.md))
- [ ] Добавление агента без кода → агент доступен для запуска по `agent_id` без изменения кода платформы ([FR-54](../../architecture/components/platform-module/prd.md))
- [ ] Удаление используемого ресурса → удаление отклоняется со списком агентов ([FR-57](../../architecture/components/platform-module/prd.md))

**Как прокликать:** Запуск валидатора на примерах: ✅ на корректных, ❌ с текстом ошибки на испорченных
