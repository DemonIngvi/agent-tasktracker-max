# Проверка двумя читателями: модели данных и интеграции (11.10.2026)

← Правило · Модель данных · [типы данных и интерфейсы](..\data-types.md)

Два независимых агента-читателя без контекста и без доступа к исходникам прочли раздел «Контракты обмена» и матрицу интерфейсов и по одной форме объяснили каждую модель (что это, кто → кому, почему так, почему такие имена, поля, что непонятно) и каждый I-код.

## Раунд 1

**Итог.** Смысл моделей и полей оба читателя поняли **одинаково** (совпадение почти полное) — сноски «почему так» читаются однозначно. Одно **расхождение** — направление [I4](../../architecture/components/agent-runner/integrations/I4.yaml) и [I7](../../architecture/components/agent-runner/integrations/I7.yaml). Главное — **«совпало, но непонятно»**: оба независимо отметили одни и те же пробелы, то есть в тексте не хватало конкретики.

## Раунд 2

Те же задания, новые независимые читатели, исправленные страницы.

**Итог.** Расхождений по смыслу **нет**: оба читателя одинаково объяснили каждую модель и интеграцию. Общие замечания стали тоньше — это уже не «что значит», а «что будет в крайнем случае». Все, кроме перечисленных в конце, исправлены в источнике.

| Объект | Оба читателя отметили | Исправлено |
|---|---|---|
| Стрелка [I1](../../architecture/components/agent-runner/integrations/I1.yaml), [I3](../../architecture/components/agent-runner/integrations/I3.yaml) | правило «стрелка = кто вызывает» нарушено: claim и heartbeat вызывает Runner | [I1](../../architecture/components/agent-runner/integrations/I1.yaml), [I3](../../architecture/components/agent-runner/integrations/I3.yaml) развёрнуты в `datamodel.py` и в `interfaces.md` четырёх спек; признак «данные в ответе» ([I1](../../architecture/components/agent-runner/integrations/I1.yaml), [I3](../../architecture/components/agent-runner/integrations/I3.yaml), [I4](../../architecture/components/agent-runner/integrations/I4.yaml)) — карточки компонентов показывают поток данных и того, кто вызывает |
| [Heartbeat](../../architecture/data/model-Heartbeat.yaml), доставка | `seq` вопроса уже есть в событиях — условие повторной доставки бессмысленно | подтверждения доставки: `CUSTOM` `decision_applied {seq}` и `message_received {id}` («получено агентом» в ленте) |
| Слово «step» | шаг процесса, итерация цикла и `stepName` под одним именем | `rule.stepId`, `run.stepId`, `task.stepId`; `Checkpoint.iteration`, `usage.iterations`; колонки `run_checkpoint.iteration` |
| Бюджеты | `spent.monthUsd` без месячного лимита; автономия и во входе, и в бандле | месячный лимит проекта в бандле (`projects.<id>.budget.month_usd` = `project_platform.budget_month_usd`); из [`PolicyInput`](../../architecture/data/model-PolicyInput.yaml) убраны автономия и `runUsd` — правило берёт лимиты из бандла |
| Три места настроек агента | [AgentDefinition](../../architecture/data/model-AgentDefinition.yaml), [AgentSettings](../../architecture/data/model-AgentSettings.yaml), [OpaBundleData](../../architecture/data/model-OpaBundleData.yaml) — что главнее | источник правды — [`AgentSettings`](../../architecture/data/model-AgentSettings.yaml); бандл и файл экспорта — производные; единая версия агента |
| Значки источника | данные форка помечены 🧩, наши ключи внутри протоколов — 📘 | значок на уровне поля (`FIELD_SRC`): [RunSummary](../../architecture/data/model-RunSummary.yaml) — ✅ форк, `CUSTOM.value`, `metadata` — 🧩 |
| [Verdict](../../architecture/data/model-Verdict.yaml) у ручного шага | `runId` обязателен, а запуска нет | `issueId` + `stepId` обязательны, `runId` — нет |
| `criteriaApproval = auto` | «сразу» и «человек подтверждает» одновременно | переписано: `auto` работает как `review` при `requireReview` или автономии R0–R1 |
| [M3Record](../../architecture/data/model-M3Record.yaml), область | как адресуются записи области `project` без задачи | `scope` — видимость ([FR-37](../../architecture/components/memory/prd.md)), ключ — задача |
| Запрос и ответ в одной модели | [SandboxClaim](../../architecture/data/model-SandboxClaim.yaml), [McpToolCall](../../architecture/data/model-McpToolCall.yaml) | поля помечены «в запросе» / «в ответе»; ошибка JSON-RPC описана |
| Примеры | [PolicyInput](../../architecture/data/model-PolicyInput.yaml) и [PolicyDecision](../../architecture/data/model-PolicyDecision.yaml) одинаковые; `{ … }` — невалидный JSON | ответ OPA — отдельным примером; в легенде: `…` — сокращение |
| Противоречие критериев двух людей | порядок «человек > процесс > агент» не различает двух людей | уточнение в [AD-20](../../architecture/decisions/AD-20.yaml): агент задаёт вопрос исполнителю задачи, шаг ждёт ответа |

**Осталось (полнота, а не понимание).** Не описаны модели ответов: ответ модели (Chat Completions), `tools/list`, токен git-провайдера, ответ Kubernetes. Это внешние API: структура — по ссылке на их спецификацию в каталоге API. Ссылки внутри страниц читателю были недоступны — ограничение проверки (читали снимок), а не документа.

**Вывод.** Объяснения читателей совпадают по смыслу; проверка по правилу закрыта.
