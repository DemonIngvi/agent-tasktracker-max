# agent-registry — конфигурация, данные, интерфейсы, отказы

← spec.md · схема · трассировка · правила

## Уровни конфигурации

| Уровень | Что | Где хранится | Область |
|---|---|---|---|
| L0 | Конфиг деплоя | S9 | платформа целиком: адреса, переключатели G1–G4, режим планирования, потолки лимитов |
| L1 | Platform module | S2 | агент: бюджеты, профили, данные guardrails, флаги планирования |
| L2 | Определение агента | S1 (+ YAML импорт) | агент: модель, инструкция, тулы, навыки, MCP, лимиты запуска |
| L3 | Запуск | задача ICPlan / `Run` | версия агента, критерии приёмки, задание |

Правило: значение берётся с самого конкретного уровня (L3 → L0), но не выше потолка L0.

## Параметры модуля

Значения и границы пересматриваются по статистике запусков (3.9) и нагрузочному тесту (4.8); правило — виды спек, таблица параметров.

| Параметр | Что задаёт | Уровень | Хранилище | По умолчанию | Почему так по умолчанию | Мин | Макс | Тип | На что опираться при выборе |
|---|---|---|---|---|---|---|---|---|---|
| `agent.model` | Алиас модели агента | L2 | S1 | — (обязательный) | модель выбирают под задачу агента | алиас из `model_list` LiteLLM | алиас из `model_list` LiteLLM | ссылка алиас LiteLLM | сложность задач и цена: сложные — сильная модель, рутинные — дешёвая |
| `agent.instruction` | Роль, правила, формат результата | L2 | S1 | — (обязательный) | без инструкции агент не знает роли | 50 символов | 20 000 символов | строка 50–20000 симв. | ≈ 5 тыс. токенов — 2,5% окна; длиннее — выносить в навыки |
| `agent.tools` | Тулы агента из каталога | L2 | S1 | нет | наименьшие права | нет | весь каталог | список tools | только тулы, без которых агент не сделает работу |
| `agent.skills` | Навыки агента из каталога | L2 | S1 | нет | наименьшие права, короткий контекст | нет | весь каталог | список skills | навыки под процедуры роли агента |
| `agent.mcp_servers` | MCP-серверы агента из каталога | L2 | S1 | нет | наименьшие права | нет | весь каталог | список servers | агенту ICPlan нужен `itsaplan-core`; остальные — по задаче |
| `agent.projects` | Проекты, где агент участник | L2 | S1 | нет | агент не видит проекты, пока его не добавили | нет | все проекты команды | список projects | только проекты, в процессах которых агент — исполнитель шага |
| `agent.version` | Версия определения, по которой идёт запуск | L3 | запуск | последняя | изменения применяются со следующего запуска | 1 | последняя | число | прежняя версия — для отката после неудачного изменения |

## Хранилища данных

| ID | Хранилище | Что хранит | Владелец | Резервирование / срок |
|---|---|---|---|---|
| S1 | PostgreSQL 17 (CloudNativePG), БД `itsaplan`, схема `public` | определения агентов: модель, инструкция, тулы, навыки, MCP-серверы, проекты, версии | ICPlan | базовые копии + WAL в S3 вне узла |
| S2 | Postgres ICPlan, схема `platform` | настройки агентов, версии, профили sandbox и памяти, данные guardrails, параметры планирования | Platform module | вместе с S1 |

## Нагрузка и развёртывание

| | |
|---|---|
| **Нагрузка** (гипотеза, R&D) | чтение определения на каждый запуск (~30 в час в пике); изменения — единицы в день |

Детали форматов — потоки.

## Отказы (FMEA)

| Отказ | Обнаружение | Поведение | Восстановление |
|---|---|---|---|
| БД ICPlan недоступна | ошибки API | определения не читаются — запуски не стартуют | восстановление БД |
| Удалён ресурс, на который ссылаются | валидация связей | удаление отклоняется | — |
| Импорт с неверной схемой | валидация YAML | импорт отклоняется | исправление YAML |
